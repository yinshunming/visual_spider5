# 可视化网页采集路线图

## 1. 路线图目标

本路线图把 [`product-spec.md`](./product-spec.md) 的首版范围拆成可独立验证的 M0–M7。每个里程碑都先关闭当前最大的风险，再向上叠加可见能力；后续 AI Coding 应按依赖顺序逐个实现，不跨里程碑并行堆叠未验证功能。

M0–M5 产物只允许在开发环境和受控 fixture 上验证，不是可供团队正式使用的发布版本。必须完成 M6 安全与可靠性加固，并通过 M7 跨平台发布验收后，才能部署给真实采集人员。

```mermaid
flowchart LR
    M0["M0<br/>远程浏览器可行性"] --> M0_5["M0.5<br/>按业务模块重排"]
    M0_5 --> M1["M1<br/>工程与账号基础"]
    M1 --> M2["M2<br/>单页配置与预览"]
    M2 --> M3["M3<br/>单页运行与导出"]
    M3 --> M4["M4<br/>列表识别"]
    M4 --> M5["M5<br/>翻页与内容页"]
    M5 --> M6["M6<br/>安全与可靠性"]
    M6 --> M7["M7<br/>跨平台首版发布"]
```

## 2. 通用完成标准

每个里程碑只有同时满足以下条件才算完成：

- 该里程碑的退出标准全部有可复现证据。
- 新行为有与风险匹配的单元、集成或端到端测试。
- Java 测试、前端测试、lint、typecheck 和构建中适用的部分全部通过。
- 数据库修改包含 Flyway migration，并说明历史数据、索引、锁和恢复方式。
- 新增配置有安全默认值、合法范围和启动时校验。
- 不把密码、Cookie、目标页面内容或结果数据写进技术日志。
- Windows 与 Linux 差异没有被硬编码进业务模块。
- 文档与 `CONTEXT.md`、ADR 和实际行为保持一致。
- 没有跨入下一里程碑的“顺手功能”。

测试分层优先级：纯领域行为先用快速测试覆盖；PostgreSQL、Playwright 和完整 HTTP 链路再用集成/端到端测试验证。不能用 mock 掩盖真实浏览器或真实 PostgreSQL 的关键差异。

## 3. M0：远程浏览器技术验证

### 目标

证明“Java/Spring Boot 服务器 + Vue Web 页面 + Playwright Chromium”能够提供足够稳定的远程浏览、元素选择和高级定位规则体验。M0 是进入产品开发前的决策门；未通过时停止 M1。

### 范围

- 最小 Spring Boot 进程启动 Playwright for Java 和 Chromium。
- 最小 Vue 页面通过 WebSocket 接收远程 JPEG 帧。
- 固定远程视口 `1280 × 720`，客户端等比显示。
- 地址导航、鼠标点击、滚轮、键盘输入、前进、后退和刷新。
- 浏览/选择模式切换。
- 根据坐标检查 DOM 元素并高亮。
- 生成候选 CSS/XPath；手写 CSS/XPath 后返回语法、匹配数和高亮。
- 配置会话关闭、超时和 Chromium 异常退出后的资源回收。
- Windows 最小 smoke test。Linux smoke 与真机 LAN 延迟验证延后到 M7（M0 决策：开发机仅 Windows、单机 localhost 基准，LAN RTT 相对 500ms 预算可忽略）。
- 比较 Playwright `Page.screencast()` 与受控频率 `Page.screenshot()` 回退方案。

### 建议 AI 工单

1. 建立最小 Java/Playwright 页面控制实验。
2. 建立 Vue/WebSocket 二进制帧显示实验。
3. 实现带序号和视口信息的输入/帧协议。
4. 实现浏览/选择模式与 DOM 高亮实验。
5. 实现 CSS/XPath 校验实验。
6. 做跨平台、延迟、内存和进程回收测量。
7. 把结论写入 `docs/spikes/remote-browser.md`，提出采用/回退决策。

### 退出标准

- 常见局域网条件下，点击或滚动后画面反馈的中位数约不超过 500ms。M0 以 localhost 基准度量（LAN RTT 相对 500ms 预算可忽略，作 LAN 代理）；真机 LAN 验证延后到 M7。
- 页面缩放、浏览器窗口缩放和滚动后，点击位置仍能选中预期元素。
- 中文输入、组合键、滚轮和页面导航可用。
- 动态页面重新渲染后，选择器验证不会依赖陈旧 ElementHandle。
- 至少 3 个并发实验会话运行 30 分钟，无无界帧队列或持续内存增长。
- 关闭/超时/崩溃后没有遗留 Chromium 或 Playwright driver 进程。
- Windows 有可重复命令和实测结果；Linux 可运行性与真机 LAN 验证延后到 M7 跨平台验收。
- 记录每个会话的内存/CPU 估算，并据此确定配置会话全局上限和最低服务器规格。

### 不做

账号、数据库、正式任务模型、结果导出、列表识别和生产级 UI。实验代码只有通过代码质量检查后才能复用；否则允许丢弃。

## 4. M0.5：按业务模块重排 M0 spike 代码

### 目标

把 M0 spike 集中在 spike 单包（原 spike 包前缀为项目早期 M0 阶段临时实验命名）的 19 个生产类与 12 个测试类，重排到 ADR-0003 规定的 `com.visualspider.<module>` 业务模块结构，为 M1 引入 `identity` 与 `task` 模块隔离重排与新功能两层行为变化，把回归风险收敛在 seam。

### 范围

- 顶层 `com.visualspider.Application`（由 M0 spike 启动类改名升顶层）；`@SpringBootApplication` 默认扫描 `com.visualspider.*`，M1+ 不需修改扫描配置。
- 6 个业务模块占位包：`identity` / `task` / `extraction` / `run` / `result` / `shared`，每个挂 `package-info.java` 写明模块边界、启用里程碑与"仅通过稳定 interface 对外暴露能力"约束。
- 18 个 spike 生产类 + 12 个 spike 测试类一对一迁入 `com.visualspider.visualbrowser.*`，旧 spike 单包清空。
- 行为零变化：所有 12 个测试原样迁移后 `./mvnw clean verify` 全绿。
- 文档同步：`docs/specs/m0.5.md` 与 `docs/spikes/remote-browser.md` 末尾收尾；roadmap 本节增补。

### 建议 AI 工单

1. T1（expand）：建 7 个新包 + `package-info.java`，把 M0 spike 启动类改名升顶层；旧 spike 单包 18 + 12 文件一行不动。
2. T2（contract）：把 18 + 12 个 spike 文件搬到 `com.visualspider.visualbrowser`，清空旧 spike 单包；`git grep -l "com\.visualspider\.spike\.m0"` 全仓库 0 命中。

> 拆票原因：M0.5 是 wide refactor（30 文件 import 一次断裂，无中间 CI 绿态），按 expand-contract 例外路径拆为 2 张工单。T1 独立绿（仅新建包 + 启动类升顶层），T2 完成时整 PR 才绿。

### 退出标准

- `./mvnw clean verify` 全绿（22 单测 + 13 IT，1 个 screencast IT 保持 `@Disabled` 状态，与重构前等价）。
- 旧 spike 单包 `git ls-files` 在 main / test 下均 0 命中。
- `git ls-files src/main/java/com/visualspider/visualbrowser/` 命中 18 个生产类；`src/main/java/com/visualspider/Application.java` 单独存在。
- `git grep -l "com\.visualspider\.spike\.m0"` 全仓库（main / test / pom / docs）0 命中。
- 19 个生产类中**只有 M0 spike 启动类改名 `Application`**，其余 18 个类名不变。
- 12 个测试类的 `@Disabled` 状态、断言、fixture 路径全部保持原样。
- `./mvnw clean package` 产出可执行 JAR；`java -jar` 启动成功（不依赖 DB）。

### 不做

引入 PostgreSQL / Flyway / 任何持久化层；引入 ArchUnit 或新 lint；引入稳定 interface / port / adapter；重构任何类的内部逻辑；解决 M0 决策门遗留（`ScreencastFrameProducerIT` 保持 `@Disabled`）；引入新依赖（pom.xml 不动）；拆分 Maven 子模块；移动 `src/test/resources/fixtures/`；新增业务功能（首个有效功能是 M1）；跑 30 分钟长跑压测（已明确延后到 M6）。

## 5. M1：工程骨架、账号与任务基础

### 目标

建立可持续开发的单 JAR 工程、PostgreSQL schema、登录权限和任务草稿外壳，为后续纵向功能提供稳定基础。

### 范围

- Maven Wrapper、Spring Boot、Vue 3 + TypeScript + Vite 的仓库结构。
- 根构建能够构建前端并生成单个可执行 JAR。
- PostgreSQL 连接、Flyway 基线和启动时配置校验。
- `identity` 模块：初始管理员、登录/退出、创建/停用账号、重置密码。
- 管理员/采集人员权限与所有权检查。
- `task` 模块：创建、命名、列表、读取、保存草稿和删除任务的基础能力。
- 任务定义 JSON 的 `schemaVersion`、乐观锁和草稿状态。
- Spring Security HttpSession、BCrypt、CSRF、`HttpOnly`/`SameSite` Cookie。
- 基础错误格式、滚动日志、健康检查和敏感信息过滤。
- Windows PowerShell 7 与 Linux 启动脚本雏形。

### 建议 AI 工单

1. 初始化 Maven/Vue 构建并产出单 JAR。
2. 建立 Flyway schema 和 PostgreSQL 集成测试入口。
3. 实现 `identity` 模块及权限矩阵测试。
4. 实现任务草稿 CRUD 与所有权隔离。
5. 建立统一错误响应、日志与健康检查。
6. 建立 Windows/Linux 开发启动说明和 smoke 命令。

### 退出标准

- 新数据库可由 Flyway 从零初始化，重复启动不会破坏 schema。
- 首次启动可以安全创建初始管理员，配置缺失时明确失败。
- 管理员可以管理账号，采集人员不能访问他人任务。
- 两个用户并发编辑同一任务时，旧版本更新被乐观锁拒绝。
- `mvn package` 生成的 JAR 能直接提供 Vue 页面与 API。
- Windows 和 Linux 都能连接 PostgreSQL、启动 JAR、登录并创建草稿任务。
- HTTP 明文风险在登录页或部署说明中可见。

### 不做

远程浏览器产品化、字段配置、预览、正式运行和导出。

## 6. M2：单页可视化配置与预览

### 目标

让采集人员完成单页任务的远程页面配置、字段定义、校验和预览，但尚不创建正式采集运行。

### 范围

- `visualbrowser` lane、配置会话生命周期和一用户一会话限制。
- WebSocket 画面/输入协议产品化，包含认证、所有权和背压。
- 地址栏、浏览/选择模式、固定视口和当前 URL。
- 系统生成元素定位规则。
- 高级 CSS/XPath 编辑、语法校验、匹配计数与高亮。
- 单页字段来源：可见文本、元素属性、链接/图片绝对 URL、当前页 URL。
- 字段清洗：首尾空白、正则提取、文本/数字/URL 类型转换、空值。
- 原始值/最终值预览和字段诊断。
- 草稿自动保存、完整校验和“可运行”状态。
- 单页预览产生一条临时结果，不写入正式结果表。
- 基础目标 URL 策略：协议、主机和公网地址校验。

### 建议 AI 工单

1. 实现 `VisualSessionManager` 与 lane 线程亲和性。
2. 产品化 WebSocket 帧/输入协议和前端远程视图。
3. 实现浏览/选择模式、元素检查与系统定位规则。
4. 实现高级 CSS/XPath 编辑器和实时反馈。
5. 实现单页字段模型、清洗与结构化诊断。
6. 实现任务校验、自动保存和草稿/可运行状态。
7. 实现与正式引擎共用逻辑的单页预览。

### 退出标准

- 用户可从 URL 打开公开静态页和 JavaScript 动态页。
- 配置会话无操作 15 分钟关闭，最长 2 小时；关闭后资源全部回收。
- 浏览模式不会意外创建规则，选择模式不会触发原页面动作。
- 系统规则与手写 CSS/XPath 对同一元素返回一致匹配结果。
- 字段匹配多个元素、字段缺失、正则失败和类型失败都有明确诊断。
- 修改入口 URL 或使规则失效会把任务恢复为草稿。
- 预览与任务保存均通过权限和 SSRF 基础检查。

### 不做

正式运行、运行历史、列表项推断、翻页、内容页和导出。

## 7. M3：单页运行、结果与导出

### 目标

完成第一个可实际使用的纵向切片：单页任务从配置一直运行到结果下载。

### 范围

- `run` 模块：任务快照、等待/运行中/终态、专用运行 lane 和用户取消。
- PostgreSQL 权威状态和 JVM 内有界调度。
- 全局 3 个运行、每用户 1 个运行的容量限制。
- 页面就绪：`DOMContentLoaded`、目标元素等待 15 秒、额外等待 0–5 秒。
- 页面失败重试 2 次；浏览器启动或入口失败进入失败状态。
- `result` 模块：JSONB 结果、结构化事件、分页查询和汇总。
- 运行进度 WebSocket 推送，不传正式运行画面。
- CSV/JSON 流式导出。
- 应用关闭与启动恢复，把遗留运行标记为已中断。
- 默认 30 天保留与到期清理。

### 建议 AI 工单

1. 实现任务快照与运行 schema/状态机。
2. 实现有界运行调度和固定 lane 执行。
3. 实现单页导航、等待、提取、重试与取消。
4. 实现结果/事件批量持久化和分页查询。
5. 实现运行进度和无画面运行详情界面。
6. 实现 CSV/JSON 流式导出。
7. 实现中断恢复和保留清理。
8. 完成单页纵向端到端测试。

### 退出标准

- 一个可运行单页任务能生成任务快照、运行记录和一条结果。
- 运行期间编辑原任务不改变当前或历史运行的快照。
- 页面超时按规则重试，取消能在有限时间内释放浏览器 lane。
- 应用强制退出后重启，遗留运行变为已中断，已写结果可导出。
- CSV 和 JSON 在 10,000 条 fixture 结果下保持流式输出，无全量内存加载。
- 用户不能读取或导出他人的运行结果。
- 到期清理正确级联删除运行、结果和事件，不删除任务。

### 不做

列表、翻页、内容页、去重和跨运行增量。

## 8. M4：列表识别与单页列表采集

### 目标

在不引入翻页和内容页的前提下，完成当前列表页的重复项推断、相对字段和批量扁平结果。

### 范围

- 点击代表项后，根据 DOM 层级和同级结构生成候选列表项规则。
- 同时高亮全部候选项并展示数量。
- 允许向上/向下调整候选范围并确认。
- 字段相对于列表项定义和验证。
- 当前列表页最多预览前 20 条记录。
- 每个列表项形成一条扁平结果。
- 单次运行内按一个或多个字段去重；空唯一键不判重。
- 运行详情显示原始、重复和最终记录数。

### 建议 AI 工单

1. 建立重复列表 HTML fixture 和推断算法基线。
2. 实现候选项高亮、祖先调整和确认交互。
3. 实现相对字段规则及系统/手写 selector 一致性。
4. 实现 20 条受限预览和字段诊断。
5. 扩展运行引擎以处理当前页多个列表项。
6. 实现唯一键计算、运行内去重和统计。
7. 完成静态/动态列表端到端测试。

### 退出标准

- 对标准列表、卡片网格和嵌套列表 fixture 能得到可解释候选项。
- 候选范围不正确时用户可以调整，而不是只能接受算法结果。
- 字段定位始终相对于当前列表项，不依赖第一条数据的绝对路径。
- CSS/XPath 手写列表项和字段规则可以替换系统规则。
- 一个列表页可预览并正式生成多条扁平结果。
- 多匹配字段不会静默取第一项，而是阻止就绪或给出明确诊断。
- 去重保留第一条，空唯一键不会导致数据被误删。

### 不做

下一页、加载更多、内容页、无限滚动和多级数据结构。

## 9. M5：翻页、加载更多与一层内容页

### 目标

完成首版列表采集主链路，使任务能够在有界条件下跨页并补充一层内容页字段。

### 范围

- 点选并重复执行“下一页”元素。
- 点选并重复执行“加载更多”元素。
- 停止条件：元素消失/禁用、无新增项、用户上限或系统硬上限。
- 从每个列表项提取明确 URL 作为内容页入口。
- 内容页字段与列表字段合并到同一结果记录。
- 内容页预览只访问前 3 条。
- 同域名并发 1，请求间隔至少 1 秒。
- 200 页面、10,000 记录、30 分钟限制。
- 页面失败继续后续数据；成功与失败并存时为部分成功。
- 遇到 `429`、持续 `403` 或验证码时停止并记录原因。

### 建议 AI 工单

1. 实现通用有界导航循环和停止原因。
2. 实现下一页规则、页面变化检测和重复页保护。
3. 实现加载更多规则、新增项检测和重复点击保护。
4. 实现内容页 URL 提取、绝对地址补全和一层访问。
5. 实现列表/内容页字段合并和 3 条内容页预览。
6. 实现限速、系统硬限制和部分成功聚合。
7. 完成翻页、加载更多、内容页失败和上限端到端测试。

### 退出标准

- 下一页和加载更多都能在元素消失、禁用或无新增项时停止。
- 循环页面、重复页和重复加载更多不会无限运行。
- 内容页必须来自明确 URL，不能通过任意动作脚本绕过范围。
- 某个内容页失败不会丢弃其他成功记录。
- 页面数、记录数和时长任一达到限制后可预测停止并记录原因。
- 429/403/验证码场景停止，不切换 UA、指纹或代理规避。
- 列表主链路端到端验收通过。

### 不做

纯无限滚动、复杂点击导航、多级内容页、目标登录态和自定义 JavaScript。

## 10. M6：安全、资源与可靠性加固

### 目标

把功能完整的系统收紧到可在可信内网长期运行的状态，重点验证 SSRF、线程模型、资源上限、恢复和数据生命周期。

### 范围

- 统一目标 URL 策略覆盖配置、预览和正式运行。
- 顶层导航、重定向和子资源请求的公网地址校验。
- IPv4/IPv6、私有/保留地址、云元数据、混合表示和 DNS 变化测试。
- WebSocket 握手、命令和会话所有权复查。
- 配置会话与运行 lane 的有界容量、背压和公平性。
- Chromium/Playwright 崩溃、超时和僵尸进程回收。
- 3 个并行运行、长列表和 10,000 结果的压力测试。
- 单实例数据库使用约束和重复启动保护。
- 运行事件、技术日志、指标和敏感信息审计。
- 保留清理、账号停用和管理员全局访问回归。
- 明确 `robots.txt` 不读取、不执行；标准 Chromium UA，不做反检测。

### 建议 AI 工单

1. 实现共用目标 URL 策略与请求拦截。
2. 建立 SSRF 恶意 fixture/测试集和残余风险说明。
3. 加固 WebSocket 权限、消息大小、速率和背压。
4. 实现 lane 容量、超时、关闭顺序和僵尸进程检测。
5. 实现单实例启动租约或数据库锁。
6. 执行并修复并发、长运行和大结果压力测试。
7. 完成日志、指标、清理和权限安全审计。

### 退出标准

- 直接 URL、重定向和页面子资源均不能访问已知内网/元数据地址。
- DNS 变化竞态的能力边界和主机防火墙建议明确记录。
- WebSocket 不能订阅、控制或猜测他人的配置会话。
- 慢客户端不会导致帧或进度消息无界积压。
- 3 个并行运行期间登录、任务查询和结果分页仍可用。
- 浏览器崩溃后 lane 能恢复服务，无遗留子进程。
- 第二个应用实例连接同一业务库时拒绝进入运行调度状态。
- 日志检查未发现密码、Cookie、完整结果值或页面内容。

### 不做

操作系统防火墙自动配置、HTTPS、公共互联网暴露、分布式 Worker 或多实例高可用。

## 11. M7：Windows/Linux 首版发布与验收

### 目标

完成两套直接部署路径、升级/恢复文档和完整用户验收，发布首个可维护版本。

### 范围

- 锁定并记录 JDK、Spring Boot、Vue、Playwright、Chromium 和 PostgreSQL 兼容版本。
- Windows PowerShell 7：环境检查、浏览器安装、启动、停止、状态和日志脚本。
- Linux：环境检查、浏览器依赖、启动脚本和可选 `systemd` unit。
- PostgreSQL 初始化、备份、迁移、恢复和保留清理说明。
- 配置参考：数据库、端口、初始管理员、容量、保留天数和日志位置。
- HTTP 可信 LAN/VPN 限制和禁止公网暴露警告。
- 从全新环境执行安装与升级演练。
- 真机局域网远程浏览延迟与 Linux 资源回收 smoke 验证（从 M0 延后）。
- 单页、列表、翻页、加载更多、内容页、取消、中断、导出和权限的验收测试。
- 修复阻断发布的问题，不新增范围外功能。

### 建议 AI 工单

1. 完成 Windows 安装/运维脚本与 clean-machine 演练。
2. 完成 Linux 安装/运维脚本与 clean-machine 演练。
3. 编写配置、数据库备份恢复和升级手册。
4. 建立首版端到端验收脚本和 fixture 站点。
5. 执行容量、权限、安全和数据生命周期发布检查。
6. 生成发布说明、已知限制和下一阶段候选项。

### 退出标准

- 全新 Windows 与 Linux 环境均能按文档完成安装、启动、登录和主链路采集。
- 真机局域网条件下，远程配置会话点击/滚动反馈中位数约不超过 500ms（从 M0 延后）。
- 单个 JAR 同时提供 Vue、REST 和 WebSocket，无 Nginx/Docker 依赖。
- 数据库升级演练成功；失败 migration 有明确恢复步骤。
- 所有首版验收项有自动化测试或可重复手工证据。
- 已知限制包含 HTTP、SSRF 残余风险、不读取 `robots.txt`、单实例和不支持登录态采集。
- 发布包没有密钥、开发数据库凭据、临时结果或测试用户密码。

### 不做

在发布阶段加入新产品能力。任何新增需求进入首版之后的候选列表。

## 12. 首版后的候选方向

以下能力不应提前混入 M0–M7，应在首版运行数据和真实用户反馈后重新排序：

- 定时调度与通知。
- 批量 URL 模板和跨运行增量去重。
- 目标网站登录态与受控凭据管理。
- 纯无限滚动和更复杂页面动作。
- 数组字段、子表和可组合清洗步骤。
- 任务共享、复制和协同编辑。
- HTTPS 内置支持或标准反向代理部署。
- 独立浏览器 Worker、多实例调度和水平扩容。
- 代理、地区路由或其他网络访问策略。
- 移动设备视口和触摸交互。

其中登录态、代理、反检测和公共 SaaS 会改变安全边界，必须重新进行 grilling 和 ADR 评估，不能作为普通小功能追加。

## 13. 后续 AI Coding 工作方式

准备启动一个里程碑时，再根据“建议 AI 工单”创建 GitHub Issues。每个 issue 应满足：

- 一个可观察结果，而不是“完成某模块”的大任务。
- 写清前置 issue、输入、输出、成功标准和明确不做项。
- 默认只改一个业务模块；跨模块任务必须说明 seam 与集成原因。
- 数据库 migration 与消费它的代码放在同一 issue 或有明确依赖。
- Bug 遵循“复现 → 回归测试 → 最小修复 → 验证”。
- 完成后把实际验证命令和未覆盖风险写进 issue/PR。

不要一次把整个里程碑交给一个无人监督的 AI 任务。推荐先实现最小 interface 和失败测试，再逐步接入真实 PostgreSQL、Playwright 与前端交互。
