# M0.5 Spec: 按业务模块重排 M0 spike 代码

> Spec 草稿；review 通过后再发到 GitHub issue tracker（`ready-for-agent`, `m0.5`）。
> 与 [`product-spec.md`](../product-spec.md)、[`architecture.md`](../architecture.md)、[`roadmap.md`](../roadmap.md)、`docs/adr/0003-organize-code-by-business-module.md` 配套。

## Problem Statement

M0 spike 代码全部聚集在 `com.visualspider.spike.m0` 单包，1133 LOC、19 个生产类、14 个测试类（6 单测 + 8 IT）。`docs/adr/0003-organize-code-by-business-module.md` 已经规定"按 `identity` / `task` / `visualbrowser` / `extraction` / `run` / `result` 等业务能力组织代码"，但这条约束目前只在文档层兑现——仓库 `git ls-files` 里只有 `com.visualspider.spike.m0.*` 一棵包结构。

如果不插入 M0.5，M1 在引入 `identity` 和 `task` 模块时就要同时承担两件事：建立新模块 + 重排 1100 行 M0 spike 代码。回归测试将覆盖两层行为变化，调试成本翻倍；同时违反 AGENTS "不为了'更优雅'重构稳定代码"——M0 spike 跑过了 14 个测试，本身就是稳定代码。

## Solution

插入 M0.5 里程碑。把 19 个 M0 spike 类与 14 个测试从 `com.visualspider.spike.m0.*` 搬到 `com.visualspider.visualbrowser.*`；`SpikeApplication` 升到顶层 `com.visualspider.Application`；同时按 ADR-0003 的模块清单（`identity` / `task` / `extraction` / `run` / `result` / `shared`）建立 6 个占位包，每个挂 `package-info.java` 说明模块边界与里程碑归属。重构保持行为零变化：所有 14 个测试原样迁移后 `./mvnw clean verify` 全绿。

## User Stories

1. As a **后端开发者接手 M1**，I want **M0 spike 代码已经按业务模块组织**，so that **我在 M1 添加 `identity` 与 `task` 时不会与 1100 行单包代码纠缠，PR diff 收敛在新模块，回归风险隔离**。
2. As a **架构 reviewer**，I want **6 个业务模块的占位包与 `package-info.java` 在 M0.5 即可见**，so that **ADR-0003 在 `git ls-files` 层就完整兑现，模块边界在 M1 落地前已经显形**。
3. As a **未来阅读 M0 spike 代码的工程师**，I want **`SpikeApplication` 不再叫 `SpikeApplication`，包前缀不再带 `spike`**，so that **包名与类名都不再暗示"这是临时实验"，而是正式模块代码**。
4. As a **CI 维护者**，I want **`mvn verify` 在 M0.5 之后仍全绿**，so that **重构没有引入行为变化；M0 现存测试集自然成为行为保护的回归网**。
5. As a **跨平台发布者（M7）**，I want **M0 决策门结论（screencast 不可用、screenshot 回退、Windows localhost 基准）在文档与代码里仍可追溯**，so that **M7 不需要回头考古 spike 决策**。

## Implementation Decisions

- **模块清单**（来自 ADR-0003）：`identity`、`task`、`visualbrowser`、`extraction`、`run`、`result`、`shared`。
- **包前缀**：`com.visualspider.<module>`，与 ADR-0003 字面对齐；`spike.m0` 段整体丢弃。
- **启动类位置**：升到顶层 `com.visualspider.Application`（不是 `com.visualspider.visualbrowser.Application`）。`@SpringBootApplication` 默认扫描 `com.visualspider.*`，让 M1 加入新模块时无需修改扫描配置；这是 M0.5 单点决定中唯一对 M1+ 有杠杆的选择。
- **`SpikeApplication` 类名**：改为 `Application`，去掉 spike 痕迹；这是 19 个生产类中**唯一**改名的类，其余 18 个保留原名。
- **`WebSocketConfig` 类名**：保留，仅去 spike 路径；它是 visualbrowser 模块的内部 Spring 配置。
- **6 个占位包**：M0.5 建立 `com.visualspider.identity`、`com.visualspider.task`、`com.visualspider.extraction`、`com.visualspider.run`、`com.visualspider.result`、`com.visualspider.shared`；每个挂 `package-info.java`，统一模板包含三段（模块名 / 启用里程碑 / "仅通过稳定 interface 对外暴露能力"约束）。
- **类的搬运粒度**：19 个生产类 + 14 个测试类一对一搬运，仅修改 `package` 声明与 `import`，不修改逻辑行、不修改可见性、不修改 Javadoc 之外的方法签名。
- **测试 fixtures**：`src/test/resources/fixtures/` 路径不动，`static.html` 与 `dynamic.html` 保持原位。
- **不引入**：Maven 多模块、ArchUnit、新接口 / port / adapter、新依赖（pom 不动）、Flyway / DB。
- **提交拆分**（分支 `codex/add-project-planning-docs`，S1）：
  - commit 1 `docs: M0 spike 收尾（CONTEXT 补两条术语 + roadmap M0/M7 联动说明）`：落工作树里两份未提交文档改动。
  - commit 2 `refactor(M0.5): 按业务模块重排 M0 spike 代码到 com.visualspider.visualbrowser`：完成 19 + 14 文件搬运 + 6 个占位包 + Application 顶层化。
- **文档同步**：
  - `docs/roadmap.md` 新增 M0.5 章节（目标 / 范围 / 退出标准 / 不做项 / 建议 AI 工单）。
  - `docs/spikes/remote-browser.md` 末尾追加一行"M0 spike 已落入 M0.5 `com.visualspider.visualbrowser` 模块"。
  - `ADR-0003` 不新增（其约束已生效），仅作为依据引用。

## Testing Decisions

- **测试搬运**：14 个测试（6 单测 + 8 IT，含 `@Disabled` 的 `ScreencastFrameProducerIT`）一对一从 `com.visualspider.spike.m0.*` 搬到 `com.visualspider.visualbrowser.*`；不动测试断言、不动 fixture 路径、不动 `@Disabled` 状态。
- **行为保护**：执行 `./mvnw clean verify`，**全绿即视为行为零变化**。这是 M0.5 唯一的核心验收信号。
- **命名清理验证**：`git grep -l "com\.visualspider\.spike\.m0"` 在 main / test / pom / 文档全 0 命中。
- **逻辑零变化验证**：`git diff --stat HEAD~1..HEAD -- '*.java'` 显示非测试类只有 `package` / `import` 改动；人工 review 确认无逻辑行变化（允许 Javadoc 微调以反映新包名）。
- **构建验证**：`./mvnw clean package` 产出可执行 JAR；`java -jar` 启动成功；不依赖 PostgreSQL（M0.5 不引入 Flyway / DB）。
- **优先级**：M0 现存测试是唯一事实基础，**M0.5 不新增测试**（M0.5 是"行为零变化重构"，不是"功能新增"；新增测试违反"一个可观察结果"原则）。
- **What makes a good test**：N/A（M0.5 不引入新测试，只搬运）；M0 既有测试覆盖已足够。

## Out of Scope

- 引入 PostgreSQL / Flyway / 任何持久化层。
- 引入 ArchUnit 或任何新的 lint / 静态分析工具。
- 引入稳定 interface / port / adapter / SPI。
- 重构任何类的内部逻辑（即使发现"这里能写得更优雅"）。
- 解决 M0 决策门遗留：`ScreencastFrameProducerIT` 保持 `@Disabled`；screencast 不可用结论保留在 `docs/spikes/remote-browser.md` §4.1。
- 引入新依赖（pom.xml 不动）。
- 拆分 Maven 子模块（保持单 JAR，与 ADR-0002 一致）。
- 移动 `src/test/resources/fixtures/`。
- 修改 19 个生产类中除 `SpikeApplication` 外的类名。
- 修改 14 个测试的测试断言或 fixture 路径。
- 新增任何业务功能（首个有效功能是 M1）。
- 跑 30 分钟长跑压测（已明确延后到 M6）。

## Further Notes

- **工作树里两份未提交文档改动**：作为 commit 1 的现成内容——`CONTEXT.md` 新增"配置会话" / "浏览模式/选择模式"两条术语；`docs/roadmap.md` 改 3 处明示 M0 只做 Windows 最小 smoke、Linux/LAN 延后 M7。
- **AGENTS.md "模块通过少量稳定 interface 隐藏实现复杂度"约束**：M0.5 不提前实现 interface，但 `package-info.java` 已经写明约束，等 M1/M2 真正落地 `identity` / `task` 时再补 interface。
- **M0.5 与 M1 的 seam**：M0.5 完成后，M1 添加 `com.visualspider.identity.*` 与 `com.visualspider.task.*` 不应触碰到 M0.5 已落地的 `visualbrowser` 任何代码；M1 的 PR diff 收敛在新模块，回归风险隔离。M0.5 是这一 seam 的成本前置。
- **AGENTS.md "实验代码只有通过代码质量检查后才能复用；否则允许丢弃"**：M0.5 选用"全部保留 + 重排"路径（grilling 决策 2 锁定 A），后续若 M2/M3 发现部分抽象不可复用，可在对应里程碑再走丢弃决策；M0.5 不预先判断。
- **M0.5 不重排 spike 决策门结论**：`docs/spikes/remote-browser.md` 第 4 节的 4 决策门（screencast→screenshot 回退 / lane 复用保留 / 全局上限 ≤3 / 最低规格 4GB+4 核）与累积残余风险清单原样保留；M6/M7 接手时按清单行动。
- **M0.5 与 ADR-0003 的关系**：ADR-0003 是"约束"，M0.5 是"约束第一阶段落地"。M1/M2 落地 `identity`/`task` 时如果需要新增接口，应在 ADR 体系内追加"模块边界第二阶段"或类似记录，避免 ADR-0003 与代码长期脱节。
