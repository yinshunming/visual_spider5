## 现状(M4 已合 main,本 spec 是叠加)

M4 已于 2026-08-17 合 main(`b58c637`)。M5 不重写、不迁移、不破 M3/M4 任何契约;所有 M4 已落地的 seam 直接复用:

| M4 能力(已落地) | M5 复用方式 |
| --- | --- |
| `TaskDefinition.schemaVersion=2` + `Limits` + `ListItemRule` + `uniqueKey` | M5 bump 到 3,新增 `paginationRule` + `FieldDefinition.scope` + `FieldDefinition.fieldKind` |
| `RunExecutor` 2 参 SPI + `RunDispatcher` 按 `task.mode` 路由(D15) | M5 新增 `MultiPageRunExecutor` + 路由表扩项,`LIST` 一律走 multi(隐式升级);`SINGLE_PAGE` 维持 `SinglePageRunExecutor` |
| `RunState.PARTIAL_SUCCESS` / `StopReason.{PAGE_LIMIT, RECORD_LIMIT, TIME_LIMIT}` | M5 复用;新增 `StopReason.{DUPLICATE_PAGE, PAGINATION_DISAPPEARED, PAGINATION_NO_NEW_ITEMS}`;复用 `HTTP_429 / HTTP_403 / CAPTCHA`(M3 占位,M5 首次触发) |
| `RunResultSink.appendBatch(runId, results, events)` + `BatchOutcome` + `unique_key_hash` 去重 | M5 复用;list 多页循环直接汇总多 batch;`content_fail_count` 通过 run_event 暴露,不入 `BatchOutcome` |
| `RunLimits.{MAX_PAGES=200, MAX_RECORDS=10000, MAX_DURATION=30min}` + `Limits.globalDefault()` | M5 `pageCount = list 页 + content 页`,`recordCount` 仅 list item;硬上限不变 |

| `LiveReadinessHook`(`PlaywrightLiveReadinessHook` 生产 bean) | M5 复用同一 hook,加 3 个 `ReadinessError` 映射 |
| `TaskSchemaUpgrader`(ApplicationRunner) | M5 加 hook 分支,静默升 V2 → V3;**已知 M4 未覆盖**:M4 `TaskSchemaUpgrader` 真实 PG V1→V2 升级路径仅单元测试,M5 真实 PG V2→V3 升级路径同样先单元测试后 IT(诚实标注) |

## 上游约束(M4 已落地的契约与 seam)

- `RunExecutor.execute(context, runId)` 2 参 SPI 不变;M5 `MultiPageRunExecutor implements RunExecutor` 必须按此签名。
- `BatchOutcome(rawCount, dedupCount, insertedCount, failedCount)` 字段不动;M5 多页循环直接累加,不在 `BatchOutcome` 加新字段(避免 M4 reader 破缺)。
- `Limits` record 形态不变;M5 仅在 `MultiPageRunExecutor` 解释 `pageCount` 时改为"list 页 + content 页"。
- `UniqueKeyHasher`(SHA-256 + canonical JSON)不变;M5 内容页字段缺值时走"全/部分空键 → null 路径",与 M4 一致。
- `BusinessErrorCode`(M1 + M4 5 项)不变;M5 加 3 项。
- `ReadyReadinessHook` 已在 M4 真 lane 同步语义上跑通;M5 不新建第二 lane,`previewWithContent` 复用现有 lane。
- 单实例约束(M3 + ADR-0006):M5 沿用;不引入第二 executor lane。
- 目标 URL 策略(M2 `BasicTargetUrlPolicy`):M5 list 页 navigate 与 content 页 navigate 共用同一策略;完整 SSRF 留 M6。
- `LoggingScrubber`(M1):M5 不新增脱敏规则;content URL 进入 `run_event.url` 视为公开目标域,脱敏沿用。
- 单 JVM 派发器 + 单 lane 顺序 sink(ADR-0006):M5 多页 executor 沿用;batch sink 不并发。

## Problem Statement

M4 让 list 任务能在当前页跑出多条扁平结果并去重。但首版列表采集的真实需求是"跨页 + 一层内容页":

- 没有"下一页"或"加载更多"规则,采集人员只能手动拼接多个"当前页任务"。
- 没有内容页字段,采集人员必须把列表页和详情页拆成两个独立任务手动合并结果。
- 没有"同域名请求间隔 1s"的限速,会触发目标站点的反爬机制(`429` / 持续 `403` / 验证码)。
- 没有"重复页保护","下一页"按钮点了但 URL 没动(JS 状态机分页)会让运行无限循环。
- 没有"加载更多"的"无新增"判定,会让运行直到 page_count 上限才停,白白占满 200 页预算。

如果不在 M5 边界内解决,会出现:

- **跨里程碑堆叠**:把"无限滚动 + JS 自定义动作"塞进 M5,违反 roadmap §9 不做项。
- **schema 演进失控**:V2 加 `paginationRule` / `fieldKind` / `scope` 不 bump `schemaVersion`,runtime reader 与历史 V2 任务边界模糊。
- **失败语义模糊**:内容页失败时若整 record 丢弃,会污染 list 字段;若整 record 丢弃 + 部分成功路径,会让"页面失败继续后续数据"语义失效。
- **限速放错层**:限速写在 lane pool 会污染 ADR-0006;写在 executor 内联会让 M6 加 system_setting 配置时无处下手。
- **重复页不识别**:next-page 模式无限循环会让 200 页上限经常误触发,但实际是同一个 page。

## Solution

M5 落地 7 张 issue,按依赖顺序推进(a → b → c → d ∥ e → f → g),排期沿用 M4 re-baseline 三阶段:

- **(a) `TaskDefinition` V3 形状 + V4 migration + 启动 hook 静默升 V3**:
  - `TaskDefinition.schemaVersion` 升至 3;新增 `paginationRule`(可空 → 等价"只跑当前页")。
  - `FieldDefinition` 加 `scope`(LIST / CONTENT,默认 LIST)+ `fieldKind`(LIST_VALUE / LIST_CONTENT_LINK / CONTENT_VALUE,默认 LIST_VALUE)。
  - V4 migration:新增索引(便于 M5 多页查询);不引入新列(`collection_task.definition` 仍 JSONB 整体读)。
  - 启动 `TaskSchemaUpgrader`(沿用 M4 同一 hook)加分支:V2 SP / V2 LIST 静默升 V3;LIST 任务无 `paginationRule` 视为合法(隐式"只跑当前页")。
  - 写入路径(reader / writer)统一走 upgrader;V3 reader 兜底再 upgrade。
  - `TaskReadiness.validateForRun` 升级支持 V3 校验。
  - Acceptance:V2 任务升级后含 `paginationRule == null`(等价单页);V3 任务可读、可校验、可起 run。

- **(b) `MultiPageRunExecutor` + dispatcher 路由 + happy-path IT**:
  - `MultiPageRunExecutor implements RunExecutor`(2 参自取 snapshot,镜像 M4 `ListRunExecutor`)。
  - `RunDispatcher` 把 `LIST` 模式任务的 executor 从 `ListRunExecutor` 切到 `MultiPageRunExecutor`;无 `paginationRule` 时退化为"只跑当前页"(等价 `ListRunExecutor` 行为)。
  - `SINGLE_PAGE` 路由不变。
  - `SinglePageRunExecutor` / `ListRunExecutor` 不删,作为单页路径的 SPI 实现保留(供 future 直接复用 + 测试 fixture)。
  - Acceptance:NEXT_PAGE 模式 2 页 fixture → 10 record → SUCCESS。

- **(c) `paginationRule` + 翻页/加载更多规则 + 重复页保护 + "无新增"判定**:
  - `PaginationRule { NavigationMode, selector, SelectorType }`,`NavigationMode ∈ { NEXT_PAGE, LOAD_MORE }`。
  - `NavigationMode=NEXT_PAGE`:点击后等 URL 变化 + 列表项数量 > 0,继续循环;URL + list-item 集合 SHA-256 双重比对命中 → `STOP_DUPLICATE_PAGE`。
  - `NavigationMode=LOAD_MORE`:点击后等 DOM 稳定 1s;list-item 数 == 点击前 → `STOP_NO_NEW_ITEMS`;连续 2 次无新增 → `STOP_NO_NEW_ITEMS`(保险)。
  - 点击元素消失 / 不可见 → `STOP_PAGINATION_DISAPPEARED`;不可点击(disabled)→ `STOP_PAGINATION_DISABLED`。
  - 同一 list page 一次只点一次(防抖);`page_count` 自增 1(list page)。
  - Acceptance:3 fixture(标准列表 / 卡片网格 / 嵌套列表)的 NEXT_PAGE 与 LOAD_MORE 模式分别跑通,各停止原因触发。

- **(d) 内容页入口 URL 抽取 + 一层内容页 navigate + retry + 失败语义**:
  - 内容页入口 = `FieldDefinition` with `scope=LIST + fieldKind=LIST_CONTENT_LINK`;M2 字段模型直接复用(`source` / `selector` / `attributeName` / `selectorType` / 清洗管线全部沿用)。
  - `uniqueKey` 不能选 `fieldKind=LIST_CONTENT_LINK` 字段(M5 readiness 校验 `UNIQUE_KEY_ON_LINK_FIELD`)。
  - 内容页 navigate 沿用 M3 page-level retry 2 次(共 3 次);重试耗尽 → content 字段全 null,list 字段保留,record 仍写 `record_count_final`,新增 `CONTENT_PAGE_FAILED` 事件 + `content_fail_count`(在 `collection_run` 加列,M5 引入)。
  - 内容页字段(`scope=CONTENT`)与 list 字段(`scope=LIST`)同名 → 按字段名合并到同一 record;同名冲突(M5 readiness `FIELD_SCOPE_CONFLICT`)拒。
  - Acceptance:`standard-list` + 内容页 fixture 跑通;内容页失败 fixture(`content-blank.html`)跑通 list 保留 / content null / record 写 final;`content_link.html`(多匹配)阻止就绪。

- **(e) `PacingPolicy` 抽象 + 限速 + 429/403/验证码停止检测**:
  - `PacingPolicy` 接口:`void beforeNavigate(URL target)`;默认实现 `SingleDomainPacingPolicy`(并发 1 + 间隔 1s)。
  - `MultiPageRunExecutor` 注入 `PacingPolicy`;每次 `page.navigate` 前调用 `beforeNavigate`。
  - `PageStopDetector`(internal,`MultiPageRunExecutor` 内部类)持有:
    - HTTP 429:`page.on("response")` 监听,任一响应 429 → 立即停止;`StopReason=HTTP_429`(复用 M3)。
    - 持续 403:滑动窗口连续 3 个 navigate 返回 403 → 停止;`StopReason=HTTP_403`(复用 M3)。
    - 验证码:每页 load 后 DOM 扫描(reCAPTCHA iframe / hCaptcha iframe / `input[name="captcha"]` / 文本含"captcha" / "验证码" / "verify you are human" / "robot")→ 停止;`StopReason=CAPTCHA`(复用 M3)。
  - 检测触发 → `run.markTerminal(state, reason)` + 写 `run_event`(message 不含堆栈 / 页面内容)。
  - 不切换 UA / 指纹 / 代理(roadmap §9 不做)。
  - Acceptance:`stop-429.html` / `stop-403.html` / `stop-captcha.html` fixture 各跑出对应 StopReason;`pacing-test.html`(每 page 1s 间隔)fixture 验证 `PacingPolicy` 调用。

- **(f) M5 readiness 校验 + `previewWithContent` + 前端 list UI 升级**:
  - readiness 新增 3 项:`PAGINATION_RULE_INVALID`(selector 实匹配 ≥ 1)/ `CONTENT_LINK_NO_MATCH`(fieldKind=LIST_CONTENT_LINK 的 selector 实匹配 ≥ 1)/ `FIELD_SCOPE_CONFLICT`(scope=LIST 与 scope=CONTENT 字段同名)。
  - `LiveReadinessHook` 扩展 `previewWithContent(def, actorId, maxContent=3)`:内部 `previewList` + 前 3 条 content fetch;同一 lane 串行 navigate;timeout 由 `LiveReadinessOutcome` 现有字段返回(M4 已含超时字段)。
  - `TaskEditView`:新增 `paginationRule` 编辑器(`NavigationMode` 切换 + selector 编辑,与 M2 选择器共享组件);`FieldDefinition` 编辑面板加 `scope` 切换 + `fieldKind` 三选一;M5 新 readiness 诊断回显。
  - `VisualSessionView`(list 模式):点代表项后还能点"翻页元素"按钮(识别 + 高亮 + 计数);字段编辑面板切换 scope 上下文;20 条列表预览 + 3 条内容页预览并排(独立分页,各自显示诊断)。
  - `RunDetailView`:新增 `pageCount` 列;`contentFailCount` 单独展示;事件流加 `LIST_PAGE_LOADED` / `CONTENT_PAGE_FETCHED` / `CONTENT_PAGE_FAILED` / `STOP_*` / `PAGINATION_*` / `DUPLICATE_PAGE`。
  - `@visualspider/contracts`:`FieldDefinition.ts` 加 `scope` + `fieldKind`;新增 `paginationRule.ts`;`schemaVersion` 升 3;`run_event` DTO 加新事件码字符串值。
  - Acceptance:list 任务配置翻页/加载更多 + content-page-link + content 字段 → READY → 启动 → 详情页四计数 + content fail 展示正确。

- **(g) E2E smoke + 多形态 fixture + 跨平台标注**:
  - `scripts/e2e/m5-smoke.ps1` / `m5-smoke.sh`:建 list-with-pagination 任务(standard-list + 2 page fixture)→ READY → 启动 → 4 计数 + content fetch 正确 → CSV 多行导出。
  - fixture:`list/pagination/`(next-page.html, load-more.html, no-new-items.html, duplicate-page.html, pagination-disappeared.html)+ `list/content-page/`(standard-list-with-content.html, content-blank.html, content-link-no-match.html, stop-429.html, stop-403.html, stop-captcha.html, pacing-test.html)。
  - Acceptance:M5 smoke 全绿;PARTIAL_SUCCESS 路径触发;Linux 标注 `not executed in M5; see M7`。

`(a)` 契约与 schema(跨 task/extraction);`(b)` 运行主干去风险;`(c)` 翻页与加载更多;`(d)` 内容页主链路;`(e)` 限速与停止检测;`(f)` readiness + UI;`(g)` 全验证。

排期(三阶段,沿用 M4 re-baseline 教训:先接线去风险,再智能配置 + 前端,最后全验证 + 合并):

- 阶段 1(接线去风险):`(a)` + `(b)` + 1 happy-path IT(NEXT_PAGE 2 页 → 10 record)。
- 阶段 2(智能配置 + 前端):`(c)` + `(d)` + `(e)` 部分(限速抽象)+ `(f)` readiness + UI。
- 阶段 3(全验证 + 合并):`(e)` 全部 + `(g)` fixture + smoke + 合 main。

M5 不引入 Docker / Redis / Testcontainers / 任何新外部依赖;不实现纯无限滚动 / 复杂动作导航 / 多级内容页 / 目标登录态 / 自定义 JavaScript / 数组字段 / 子表 / 跨运行增量 / 完整 SSRF / 定时调度。

## User Stories

1. As a **首版采集人员**,I want **在 LIST 任务上点选"下一页"元素让系统自动跨页抽取**,so that **我可以一次配置覆盖整个分页列表,而不是手动拼接多个当前页任务**。
2. As a **首版采集人员**,I want **在 LIST 任务上点选"加载更多"元素让系统自动追加列表项**,so that **支持 JS 渲染的单页增长型列表,而不是只能处理传统分页**。
3. As a **首版采集人员**,I want **从每个列表项里抽取一个明确的内容页 URL 作为补充字段的入口**,so that **内容页字段能自动进入同一记录,而不是手工合并多个任务的 CSV**。
4. As a **首版采集人员**,I want **系统自动检测"下一页"按钮是否真的翻页了(URL + 内容双保险),停止重复页循环**,so that **JS 状态机分页站点不会无限循环**。
5. As a **首版采集人员**,I want **加载更多点击后如果列表项不再增长就自动停止**,so that **不会让 page_count 上限白白耗尽在重复点击上**。
6. As a **首版采集人员**,I want **内容页 fetch 失败时保留 list 字段,content 字段填 null,记录仍写入 final**,so that **一条记录不会因为详情页失败被完全丢弃**。
7. As a **首版采集人员**,I want **同一目标域名每次 navigate 之间至少 1 秒间隔**,so that **不会触发目标站点的限流或反爬**。
8. As a **首版采集人员**,I want **遇到 429 / 持续 403 / 验证码时自动停止并记录明确原因**,so that **我能区分"网络限流"和"目标站点要求验证"**。
9. As a **首版采集人员**,I want **list 任务在 200 页 / 10000 条 / 30 分钟任一达限时按明确 stopReason 停止**,so that **长列表不会跑超时也不丢原因**。
10. As a **首版采集人员**,I want **preview 阶段就能看到内容页字段(最多 3 条)的取值**,so that **配置期间就能确认内容页规则正确,不必起 run**。
11. As a **首版采集人员**,I want **run_event 流能展示翻页 / 内容页 / 停止检测的具体事件**,so that **运行结束后我能追溯每一步发生了什么**。
12. As a **M6 接手人**,I want **M5 把"1 秒间隔"和"3 个连续 403"配置点都抽到 `PacingPolicy` 接口与 `PageStopDetector` 常量**,so that **M6 仅替换实现即可入 `system_setting` 而不动调用点**。
13. As a **M6 接手人**,I want **M5 的 `paginationRule` 与 `content-page-link` 都走 TaskDefinition V3 JSONB 而非新表**,so that **M6 升级 `BasicTargetUrlPolicy` 时调用点不变**。
14. As a **M6 接手人**,I want **M5 的重复页保护与"无新增"判定的阈值都在 `MultiPageRunExecutor` / `PageStopDetector` 内部硬编码并有清晰常量**,so that **M6 加 system_setting 时只改读取路径**。
15. As a **M7 接手人**,I want **M5 smoke 脚本沿用 M4 `m4-smoke.ps1` 风格(`m5-smoke.ps1` + `.sh` 占位 + Linux 标注)**,so that **M7 跨平台验收只需把 `.sh` 落到 Linux 真机**。
16. As a **首版审计员**,I want **M5 的 `run_event.message` 仍不复制堆栈、完整页面内容或结果字段值**,so that **M1/M2/M3/M4 的脱敏规则继续覆盖多页 / 内容页路径**。
17. As a **首版审计员**,I want **M5 的内容页 URL 进入 `run_event.url` 时仍只记公开目标域,不让私有 / 内网 URL 泄露到运行详情**,so that **M6 完整 SSRF 之前不引入新泄露面**。

## Implementation Decisions

### D1. `TaskDefinition` 升级到 V3

```java
public record TaskDefinition(
        int schemaVersion,         // bump 2 -> 3
        TaskMode mode,
        String startUrl,
        Viewport viewport,
        WaitPolicy waitPolicy,     // M3 加, 可选
        Limits limits,             // M4 加, 可选 -> 全局默认
        ListItemRule listItemRule, // M4 加, LIST 模式必填
        List<UniqueKeyField> uniqueKey, // M4 加, 可空 -> 不去重
        PaginationRule paginationRule,  // M5 加, 可空 -> 等价"只跑当前页"
        List<FieldDefinition> fields) { // M5 升级: FieldDefinition 加 scope + fieldKind

    public TaskDefinition {
        if (fields == null) fields = List.of();
        if (waitPolicy == null) waitPolicy = new WaitPolicy(0);
        if (limits == null) limits = Limits.globalDefault();
        if (uniqueKey == null) uniqueKey = List.of();
        // paginationRule 可空: MultiPageRunExecutor 检测到 null 时退化为"只跑当前页"
        // 不引入第二个 record 构造器; 沿用 M4 紧凑构造器签名兼容模式
    }

    // M3 / M4 兼容构造器: paginationRule 传 null, 由紧凑构造器接受
    public TaskDefinition(int schemaVersion,
                          TaskMode mode,
                          String startUrl,
                          Viewport viewport,
                          WaitPolicy waitPolicy,
                          Limits limits,
                          ListItemRule listItemRule,
                          List<UniqueKeyField> uniqueKey,
                          List<FieldDefinition> fields) {
        this(schemaVersion, mode, startUrl, viewport, waitPolicy,
             limits, listItemRule, uniqueKey, null, fields);
    }
}

public record PaginationRule(
        NavigationMode mode,           // NEXT_PAGE / LOAD_MORE
        String selector,               // 必填, 翻页/加载更多元素的 CSS/XPath
        SelectorType selectorType) {   // 默认 CSS

    public PaginationRule {
        if (mode == null) throw new IllegalArgumentException("paginationRule.mode 不能为空");
        if (selector == null || selector.isBlank())
            throw new IllegalArgumentException("paginationRule.selector 不能为空");
        if (selectorType == null) selectorType = SelectorType.CSS;
    }
}

public enum NavigationMode {
    /** 点击后 URL 变化, 内容列表全替换; 重复页保护用 URL + list-item hash 双重比对 */
    NEXT_PAGE,
    /** 点击后 URL 不变, list-item 数量增长; "无新增"判定 */
    LOAD_MORE
}
```

- `schemaVersion=2` 任务通过 `TaskSchemaUpgrader` 升级:M4 已有的 upgrader 加分支,扫描 `schemaVersion=2` 的 task,直接 `jsonb_set` 补 `paginationRule = null` + `schemaVersion=3`;不引入数据变更。
- `schemaVersion=1` 任务先走 M4 升 V2 分支,再走 M5 升 V3 分支(同一 upgrader 内顺序处理)。

### D4. `MultiPageRunExecutor` + dispatcher 路由

```java
final class MultiPageRunExecutor implements RunExecutor {
    // 2 参 RunExecutor SPI (execute(context, runId)), 内部自取 snapshot,
    // 镜像 M4 ListRunExecutor 签名。
    private final PagingExecutor pagingExecutor;   // (c) 翻页循环
    private final ContentPageFetcher fetcher;      // (d) 内容页 navigate
    private final PacingPolicy pacingPolicy;       // (e) 限速
    private final PageStopDetector stopDetector;   // (e) 停止检测
    private final RunResultSink sink;
    private final CollectionRunRepository repo;
    private final Clock clock;

    @Override
    public void execute(RunExecutionContext ctx, long runId) {
        TaskSnapshot snap = repo.findById(runId).snapshot();
        try (ctx) {
            var page = openPage(snap.definition().startUrl());  // M4 single BrowserContext + single Page 沿用
            page.waitForLoadState(LoadState.DOMContentLoaded);
            TargetUrlPolicy.validate(page.url(), snap.definition().startUrl());
            page.waitForSelector(snap.definition().listItemRule().selector(),
                                 new WaitOptions().timeout(15s));

            // 多页循环: 翻页/加载更多 + 重复页保护 + 无新增判定 + 限速 + 停止检测
            pagingExecutor.runPages(snap, page, ctx, runId,
                                    (listPage) -> processListPage(snap, listPage, ctx, runId));

            // 终态: PARTIAL_SUCCESS / SUCCESS / FAILED (沿用 M4 D7 路径)
            repo.terminal(runId, computeState(runId), computeStopReason(runId), clock.now());
        } catch (Exception ex) {
            handleRunFailure(runId, ex);
        } finally {
            closeContext();
        }
    }

    /** 单页 list 处理: 每 item 抽取 list 字段 + content-page-link 字段, navigate 内容页, 合并 content 字段 */
    private void processListPage(TaskSnapshot snap, ListPage page,
                                 RunExecutionContext ctx, long runId) {
        // 1. 抽取 list-item (沿用 M4 ListRunExecutor 路径)
        var listItems = page.querySelectorAll(snap.definition().listItemRule().selector(),
                                              snap.definition().listItemRule().selectorType());
        for (ElementHandle item : listItems) {
            if (ctx.isCancelRequested() || isOverLimits(ctx)) break;

            var record = previewSingleItem(item, snap);
            // 2. content-page-link 字段抽取 (M5 D4)
            var contentUrl = record.contentLinkValue();
            if (contentUrl != null && !contentUrl.isBlank()) {
                // 3. 内容页 navigate + retry (D8) + 限速 (D10)
                pacingPolicy.beforeNavigate(contentUrl);
                var content = fetcher.fetchWithRetry(snap, contentUrl);  // 2 retry, 共 3 次
                if (content.ok()) {
                    record.mergeContentFields(content.fields());
                } else {
                    record.markContentFailed();  // content 字段全 null, list 保留 (D7)
                }
            }
            // 4. 入 sink (M4 BatchOutcome 路径, 不破契约)
            sink.appendBatch(runId, List.of(record.toResultRecord()), batchEvents(record));
        }
    }
}
```

- `MultiPageRunExecutor` 与 `ListRunExecutor` / `SinglePageRunExecutor` 同 SPI;M5 在 `RunDispatcher` 把 `LIST` 模式路由从 `ListRunExecutor` 切到 `MultiPageRunExecutor`(M4 D15 路由表扩项;**不**新增 `RunExecutorRouter` 抽象)。
- `paginationRule == null` → `MultiPageRunExecutor` 走"只跑当前页"分支,等价 `ListRunExecutor` 行为(隐式升级,无破坏性)。
- `SinglePageRunExecutor` / `ListRunExecutor` 不删,作为单页路径实现保留(M4 acceptance 不破)。

### D5. `PaginationRule` 翻页/加载更多 + 重复页保护 + "无新增"判定

```java
final class PagingExecutor {
    private final PacingPolicy pacingPolicy;
    private final PageStopDetector stopDetector;
    private final ContentHasher contentHasher;  // SHA-256 of normalized list-item text
    private final Clock clock;

    /**
     * @param perPage 回调: 每张 list 页加载后调用 (含初始页 + 每张翻页后页)
     */
    void runPages(TaskSnapshot snap, Page page, RunExecutionContext ctx,
                  long runId, Consumer<ListPage> perPage) {
        var visitedUrls = new HashSet<String>();
        var visitedContentHashes = new HashSet<String>();
        var lastItemCount = 0;
        int consecutiveNoNew = 0;
        int pageCount = 0;

        // 初始页
        perPage.accept(new ListPage(page, ++pageCount));
        visitedUrls.add(page.url());
        visitedContentHashes.add(contentHasher.hash(page));

        // 翻页循环
        while (snap.definition().paginationRule() != null) {
            if (ctx.isCancelRequested() || stopDetector.shouldStop(runId)) break;

            var pagination = snap.definition().paginationRule();
            // 1. 限速
            pacingPolicy.beforeNavigate(page.url());
            // 2. 点击翻页/加载更多元素
            var clicked = clickPagination(page, pagination);
            if (clicked == ClickResult.DISAPPEARED) {
                stopDetector.record(runId, StopReason.PAGINATION_DISAPPEARED);
                break;
            }
            if (clicked == ClickResult.DISABLED) {
                stopDetector.record(runId, StopReason.PAGINATION_DISABLED);
                break;
            }
            // 3. 等 DOM 稳定
            page.waitForLoadState(LoadState.DOMContentLoaded);

            if (pagination.mode() == NavigationMode.NEXT_PAGE) {
                // 4a. URL + content hash 重复检测
                var newUrl = page.url();
                var newHash = contentHasher.hash(page);
                if (visitedUrls.contains(newUrl) || visitedContentHashes.contains(newHash)) {
                    stopDetector.record(runId, StopReason.DUPLICATE_PAGE);
                    break;
                }
                visitedUrls.add(newUrl);
                visitedContentHashes.add(newHash);
            } else { // LOAD_MORE
                // 4b. 无新增检测
                sleep(1000);  // 等 DOM 稳定 1s (与 PacingPolicy 默认间隔对齐)
                var curCount = page.querySelectorAll(snap.definition().listItemRule().selector()).size();
                if (curCount <= lastItemCount) {
                    consecutiveNoNew++;
                    if (consecutiveNoNew >= 2) {  // 保险: 连续 2 次无新增
                        stopDetector.record(runId, StopReason.PAGINATION_NO_NEW_ITEMS);
                        break;
                    }
                    continue;  // 不算 page_count++
                }
                consecutiveNoNew = 0;
                lastItemCount = curCount;
            }

            pageCount++;
            if (pageCount >= snap.definition().limits().pageLimit()) {
                stopDetector.record(runId, StopReason.PAGE_LIMIT);
                break;
            }
            perPage.accept(new ListPage(page, pageCount));
        }
    }

    private enum ClickResult { OK, DISAPPEARED, DISABLED }
}
```

- `contentHasher`:沿用 M4 `UniqueKeyHasher` SHA-256 + canonical JSON 思路,但输入是"list-item 规范化文本串联"(每个 item 的 `innerText` 去空白后 `||`);不写 DB,仅内存比对。
- `pageCount`:list 页 + content 页总和(见 D6);翻页循环每次成功 next/load 触发后 +1(content 页计数见 D6)。
- 防抖:同 list page 内只点一次翻页元素,即使 executor 重入也不重复触发(`PagingExecutor` 实例级 `lastClickedAt`)。
- 取消检查点:每张 list 页 perPage 回调前 + 终止条件判定后。

### D6. 内容页入口 URL 抽取 + 一层内容页 navigate + retry + 失败语义

```java
final class ContentPageFetcher {
    private final PacingPolicy pacingPolicy;
    private final PageStopDetector stopDetector;
    private final Clock clock;

    /**
     * 沿用 M3 page-level retry 2 次 (共 3 次); 重试耗尽 -> return ContentFetch.failed(...)
     * content URL 已经在 D5 走过 beforeNavigate; 内容页 navigate 前不再调用 beforeNavigate.
     */
    ContentFetchResult fetchWithRetry(TaskSnapshot snap, String contentUrl) {
        if (!TargetUrlPolicy.isAllowed(contentUrl)) {
            return ContentFetchResult.failed("URL_NOT_ALLOWED", contentUrl);
        }
        Exception last = null;
        for (int attempt = 1; attempt <= 3; attempt++) {
            try {
                var contentPage = openContentPage(contentUrl);  // 独立 navigate, 不复用 list page
                contentPage.waitForLoadState(LoadState.DOMContentLoaded);
                TargetUrlPolicy.validate(contentPage.url(), contentUrl);
                var fields = extractContentFields(snap, contentPage);  // 抽取 scope=CONTENT 字段
                contentPage.close();
                return ContentFetchResult.ok(fields);
            } catch (Exception ex) {
                last = ex;
                if (attempt < 3) sleep(1000 * attempt);  // 退避
            }
        }
        return ContentFetchResult.failed("RETRY_EXHAUSTED", last.getMessage());
    }

    private Map<String, String> extractContentFields(TaskSnapshot snap, Page page) {
        // 沿用 ExtractionPreview.preview, 但 scope=CONTENT 字段从 content page 抽取
        // 同一 listItem 上下文无关 (content page 没有 listItem, 字段直接对整页查询)
        return ExtractionPreviewImpl.previewScoped(snap.definition().fields().stream()
            .filter(f -> f.scope() == FieldScope.CONTENT).toList(), page);
    }
}
```

- 内容页失败语义(D7 实施):
  - list 字段保留;`fieldKind=LIST_CONTENT_LINK` 字段(URL 本身)仍写入 record;
  - `scope=CONTENT` 字段全 null;
  - record 仍写 `record_count_final`(走 `RunResultSink.appendBatch`);
  - `content_fail_count++`(写入 `collection_run.content_fail_count`);
  - `run_event` 写 `CONTENT_PAGE_FAILED` (WARN, `error_code=RETRY_EXHAUSTED`);
  - 不阻塞 run,不增加 `fail_count`;不影响 PARTIAL_SUCCESS 判定。
- `MultiPageRunExecutor.processListPage` 的 `record.markContentFailed()` 调用 sink 时,把 `content_fail_count` 增量通过 batch events 路径累加(sink 在 `appendBatch` 末尾读 events 增 `content_fail_count` 列,见 D8)。
- 内容页 URL 抽取失败的两种情形(M5 readiness 校验):
  - selector 多匹配 → `MULTIPLE_MATCH`(沿用 M4);`fieldKind=LIST_CONTENT_LINK` 同样要 `count == 1`。
  - selector 不匹配 → `CONTENT_LINK_NO_MATCH`(M5 readiness 新增);`TaskReadiness` 拒 READY。

### D9. `PacingPolicy` 抽象

```java
public interface PacingPolicy {
    /** 在 navigate(targetUrl) 之前调用; 默认实现 SingleDomainPacingPolicy */
    void beforeNavigate(URL targetUrl);
}

public final class SingleDomainPacingPolicy implements PacingPolicy {
    private static final Duration INTERVAL = Duration.ofSeconds(1);
    private final ConcurrentHashMap<String, Instant> lastByDomain = new ConcurrentHashMap<>();

    @Override
    public void beforeNavigate(URL targetUrl) {
        var domain = targetUrl.getHost();
        var now = Instant.now();
        var last = lastByDomain.compute(domain, (k, prev) -> {
            if (prev == null || Duration.between(prev, now).compareTo(INTERVAL) >= 0) {
                return now;
            }
            return prev;  // 不更新, 让 next 调用重新判定
        });
        var elapsed = Duration.between(last, now);
        if (elapsed.compareTo(INTERVAL) < 0) {
            sleep(INTERVAL.minus(elapsed).toMillis());
        }
        lastByDomain.put(domain, Instant.now());
    }
}
```

- 单实例约束:跨 executor 全局唯一(MultiPageRunExecutor 是单 JVM 单 lane,所以"并发 1"自动满足;`beforeNavigate` 主要强制"间隔 ≥ 1s")。
- M6 替换:`PacingPolicy` 实现入 `system_setting`,`SingleDomainPacingPolicy` 变 fallback 默认;调用点(`MultiPageRunExecutor` 注入)不变。

```java
final class PageStopDetector {

    private static final List<String> CAPTCHA_SELECTORS = List.of(

        "iframe[src*='hcaptcha']",

        "[class*='captcha']",
        "[id*='captcha']"

    );

    private final Clock clock;

    void recordResponse(int status, String url) {
        if (status == 429) onStop.accept(StopReason.HTTP_429);  // 复用 M3
        else if (status == 403) {
            recentForbidden.addLast(true);

            if (recentForbidden.size() == FORBIDDEN_WINDOW
                && recentForbidden.stream().allMatch(b -> b)) {
                onStop.accept(StopReason.HTTP_403);  // 复用 M3
            }
        }
    }

    void checkCaptcha(Page page) {
        for (var sel : CAPTCHA_SELECTORS) {
            if (page.querySelector(sel) != null) {
                onStop.accept(StopReason.CAPTCHA);  // 复用 M3
                return;
            }
        }
        var text = page.innerText("body").toLowerCase();
        for (var tok : CAPTCHA_TEXT_TOKENS) {
            if (text.contains(tok)) {
                onStop.accept(StopReason.CAPTCHA);
                return;
            }
        }
    }

    boolean shouldStop(long runId) {
        // RunRepository 读 stop_reason 是否非 null (终态)
        return false;  // 实际实现读 run
    }
```

### D11. M5 readiness 校验

| 字段 | 校验规则 | 失败码(`BusinessErrorCode`) |
| --- | --- | --- |
| `schemaVersion` | == 3 | `TASK_SCHEMA_OUTDATED`(沿用 M4) |
| `paginationRule.mode` | 提供 `paginationRule` 时实匹配 ≥ 1(点击元素 visible) | `PAGINATION_RULE_INVALID` |

### D17. `run_event` 新增事件码


## Further Notes

- **M4 -> M5 契约兑现**:
  - `RunExecutor` 2 参 SPI + dispatcher 模式路由 + `BatchOutcome` + `PARTIAL_SUCCESS` + `unique_key_hash` + `RunLimits` + `DomState.query` + `WaitPolicy` + `Limits.globalDefault()` + `LiveReadinessHook` 全部按 M3 / M4 "宽接口窄实现"承诺直接复用,M5 不拓宽 M3/M4 任何接口。
  - `BatchOutcome` 新增字段 `contentFailCount`(默认 0)向后兼容;M4 reader 返 0;不破 M4 acceptance。
  - `StopReason` 新增 4 个 enum 值(D16)与 M3 / M4 既有值并存;`HTTP_429 / HTTP_403 / CAPTCHA` M3 已占位,M5 首次真正触发。
  - `RunResultSink.appendBatch` 接口签名不变;`content_fail_count` 累加在 sink 内部 SQL 末尾,不破 M4 调用点。
  - `ListRunExecutor` / `SinglePageRunExecutor` 不删,作为 SPI 实现保留(M4 acceptance 不破);`MultiPageRunExecutor` 是 M5 新增实现。
- **M5 -> M6 契约**:
  - `PacingPolicy` 接口 + `PageStopDetector` 常量(`FORBIDDEN_WINDOW=3` / `INTERVAL=1s` / `CAPTCHA_SELECTORS` / `CAPTCHA_TEXT_TOKENS`)M6 加 `system_setting` 时只改实现 + 读取路径。
  - `TaskDefinition` V3 JSONB 不引入新表;M6 升级 `BasicTargetUrlPolicy` 时调用点不变。
  - `TaskSchemaUpgrader` 与 M4 顺序同 hook,M6 叠加单实例租约留 hook 点。
- **M5 -> M7 契约**:
  - `m5-smoke.ps1` 沿用 `m4-smoke.ps1` 风格;`m5-smoke.sh` 占位 + 标注 `not executed in M5; see M7`。
  - `PaginationRule` + `FieldDefinition.{scope, fieldKind}` + `BatchOutcome.contentFailCount` + `StopReason` 新值全部进 `@visualspider/contracts`,M7 端到端验收脚本可生成对应 fixture。
- **schemaVersion bump 的诚实性**:旧 V1 / V2 reader 可读 V2 / V3 任务(`@JsonIgnoreProperties`);新 V3 reader 也可读 V1 / V2(upgrader 路径);运行时 V3 才允许 LIST 起 run(M4 已要求 V2,V5 加 V3),V1 / V2 任务经 upgrader 升 V3 后再运行。
- **`content_fail_count` 与 `fail_count` 语义区分**:M4 `fail_count` 代表 sink 行级异常(SQLState 22x / 23x / 资源耗尽);M5 `content_fail_count` 代表"内容页 navigate 失败(retry 耗尽)+ content 字段全 null";两者并存于 `collection_run`,互不影响。
- **重复页保护的诚实性**:`contentHasher` 输入是 list-item 规范化文本;对 JS 状态机分页(URL 不变但内容变)与 query 参数分页(URL 变但内容同)都能识别。
- **不切换 UA / 指纹 / 代理**:M5 检测到 429 / 持续 403 / 验证码 → 退避停止,**不**做反检测;这是 roadmap §9 + 产品 §7 明确边界,review 检查点。
- **与 roadmap §9 退出标准**:
  - 下一页和加载更多都能在元素消失、禁用或无新增项时停止 → (c) `MultiPageRunIT.loadMoreHappyPath` / `paginationDisappeared` / `duplicatePage`。
  - 循环页面、重复页和重复加载更多不会无限运行 → (c) `duplicatePage` + (g) smoke step 7。
  - 内容页必须来自明确 URL,不能通过任意动作脚本绕过范围 → (d) `ContentPageFetch` 只走 `LIST_CONTENT_LINK` 字段值;无自定义 JS 路径。
  - 某个内容页失败不会丢弃其他成功记录 → (d) `ContentPageRunIT.contentPageBlank` + (g) smoke step 8。
  - 页面数、记录数和时长任一达到限制后可预测停止并记录原因 → (d)(e) `MultiPageRunIT` + `RunDetailV3IT`。
  - 429/403/验证码场景停止 → (e) `StopDetectorIT` + (g) smoke step 9。
  - 列表主链路端到端验收通过 → (g) `m5-smoke.ps1`。
