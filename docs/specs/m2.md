# M2 Spec: 单页可视化配置与预览

> Spec 草稿；review 通过后再发到 GitHub issue tracker（`ready-for-agent`, `m2`）。
> 与 [`product-spec.md`](../product-spec.md)、[`architecture.md`](../architecture.md)、[`roadmap.md`](../roadmap.md) §6、`docs/adr/0003-organize-code-by-business-module.md`、`docs/adr/0004-config-and-run-lane-pools-are-independent.md`、`docs/adr/0005-task-readiness-is-syntax-only.md` 配套。
> 上游约束：M1 已落地的 `identity` / `task` / `shared` 三模块（`m1.md` 退出标准已通过）；M0 spike 已迁入 `com.visualspider.visualbrowser.*`（`m0.5.md` 退出标准已通过）；M0 spike 决策门结论保留（`docs/spikes/remote-browser.md` §4）。

## Problem Statement

M1 已经给后端准备好了稳定 seam：`IdentityAccess` / `TaskCatalog` / `TaskReadiness` / `TaskSnapshotFactory` 四个 interface 都已经定义并被单测覆盖；`app_user` / `collection_task` / `system_setting` 三张表已经上线；Spring Security + CSRF + Cookie 会话已经接通；统一错误响应、滚动日志、健康检查已经就绪。但是：

- 采集人员**不能**打开一个远程浏览器页面去做元素点选；
- 任务定义里的字段、定位规则、清洗规则**没有可视化编辑面**；
- 草稿是否能跑、字段是否能在真实页面上取到值，**没有自动验证**；
- 用户无法在没有 Run 引擎的情况下提前看到"我这条任务跑起来会长什么样"。

如果不在 M2 把这条纵向切片打通，M3 进入运行调度时就要同时承担 4 件事：任务快照 + 运行 schema + 等待/运行中状态机 + 真实页面提取，并且每一层的 bug 都会污染上一层的调试。M2 是配置侧与运行侧的桥接点。

M2 也是 M0 spike 代码第一次真正产品化：`BrowserLane` / `VisualSession` / `CandidateGenerator` 等 spike 类至今仍直接暴露在 `com.visualspider.visualbrowser` 包顶层，没有稳定 interface 包装；spike §5 残余风险表第 1、2、6、11 条的兑现（adapter seam、协议认证、session 关停校验、validateSelector 规范化）必须在 M2 落地。

## Solution

把 M2 落地为 5 张 issue，按依赖顺序推进（a → b → c → d → e）：

- **(a) VisualSessionManager 产品化 + 双 lane 池 + WebSocket 身份握手**：M0 spike 包顶层 18 个类迁入 `spi/` / `internal/`，新增 `VisualSessionManager` interface（封装 `open / get / close / heartbeat / handleCommand`）+ `ConfigLanePool`（固定 3 lane）；`HandshakeInterceptor` 验证 `JSESSIONID` cookie + CSRF token + sessionOwner；frameSenders 线程池 `@PreDestroy` 关闭；新增 15min 空闲 / 2h 最长生命周期；新增 SSRF 基础校验（仅 scheme 与主机名语法）。
- **(b) 浏览/选择模式 + 系统定位规则 + CSS/XPath 高级编辑器**：把 M0 `InputCommand` / `SelectionRecord` 接入 mode 字段；`SelectModeHandler` 与 `BrowseModeHandler`；`CandidateGenerator` 升级为 `SystemLocatorGenerator`，生成 N 个候选（specificity 排序 + 稳定度评分）；新增 `AdvancedSelectorEditor` UI（防抖 300ms 实时校验、匹配数、当前页高亮、语法错误定位）；新增"查看候选"切换。
- **(c) 字段模型产品化 + 清洗管道 + 类型转换 + 预览管道**：扩展 `FieldDefinition`（`source` enum：`VISIBLE_TEXT` / `ATTRIBUTE` / `LINK_URL` / `IMAGE_URL` / `PAGE_URL`；`attributeName`、`regex`、`trim`、`required` 全部启用）；新增 `CleaningPipeline`（trim → regex extract → type convert → null-on-empty）；`resultType` 转换失败保留原始值 + `TYPE_CONVERSION_FAILED` 诊断；`ExtractionPreview.preview(definition, domState)` 在浏览器 lane 内执行，返回 `PreviewResult`（字段原始值 + 最终值 + 诊断）。预览与未来运行共用同一实现。
- **(d) 任务校验完整化 + 自动保存 + 可运行状态**：实现 `TaskReadiness.validateForRun`（基于 ADR-0005 语法就绪语义）；CSS/XPath 语法校验引入 `Jsoup.parse` 与 JDK `XPathFactory`；session 内 `EditingBuffer` 维护"当前编辑中定义"，防抖 5s 调用 `TaskCatalog.saveDraft`，乐观锁冲突重试一次；session 关闭前同步最后保存；session 内编辑**不**触发 `status` 字段变更，仅最近一次保存决定 `status`。
- **(e) 前端远程视图 + 配置 UI + 横切 smoke**：Vue 3 单页 + Vite，集成 WS 客户端；地址栏、浏览/选择模式切换器、当前 URL 显示、远程页面画面（1280×720 等比缩放）、字段编辑面板（名称 / 来源 / 选择器 / 属性名 / 正则 / 类型 / 必填）、诊断面板、原始/最终值对比、预览按钮、保存指示；smoke.ps1/sh 跑通"登录 → 建草稿 → 开 session → 浏览 → 选元素 → 编辑字段 → 预览 → 保存 → 退出 session"主链路。

(a)(b)(c)(d) 是后端接口与契约；(e) 是前端 + 端到端 smoke。五张 issue 必须顺序推进：(b)(c)(d) 强依赖 (a) 的 stable seam；(e) 强依赖 (a)(b)(c)(d) 全部完成。

M2 不引入 Docker / Redis / Testcontainers / 任何新外部依赖；不复用 M1 schema（`collection_task` 已支持足够字段）；不实现运行调度、列表模式、翻页、内容页、导出、SSRF 严格校验。

## User Stories

1. As a **首版采集人员**，I want **打开一个任务后看到一个远程浏览器画面，能像在自己电脑上一样浏览目标网站**，so that **我能在不安装客户端的情况下用熟悉的鼠标和键盘完成"到达目标页面"这一步**。
2. As a **首版采集人员**，I want **切换到选择模式后，点击页面元素就能把它定为某个字段的来源**，so that **我不需要手写 CSS 或 XPath；系统给我生成最稳的一条，我还能看到其他候选**。
3. As a **首版采集人员**，I want **手写 CSS 或 XPath 后实时看到匹配数量与高亮**，so that **我能立刻判断这条规则是否选到了我想要的内容，不用每次都保存预览**。
4. As a **首版采集人员**，I want **选错元素或写错选择器时，左边选择器面板会显示明确诊断（语法错误位置、0 匹配警告、多匹配警告）**，so that **我能直接定位问题**，不用看 Java 控制台。
5. As a **首版采集人员**，I want **定义好字段后点"预览"按钮立即看到每个字段的原始值与最终值**，so that **我能在不启动正式运行的情况下验证我的任务能不能跑**。
6. As a **首版采集人员**，I want **任务的所有修改自动 5 秒防抖保存**，so that **我不小心关掉标签页或浏览器也不会丢失工作**。
7. As a **首版采集人员**，I want **看到任务状态是「可运行」时，能确信它在保存的版本上语法完全合法**，so that **我不需要担心状态显示与实际能不能跑不一致**。
8. As a **首版采集人员**，I want **字段的正则捕获失败或类型转换失败时，UI 上能看到具体哪个字段、什么原因，原始值还在**，so that **我能保留数据并修正规则，不会因为一个错误的类型选择就丢掉整条记录**。
9. As a **首版管理员**，I want **同时只能有一个用户占用一个配置会话，第二个用户登录不会被静默接受**，so that **服务器资源（3 个配置 lane）不会被无限制占用**。
10. As a **首版运维**，I want **配置会话 15 分钟无操作自动关闭、2 小时强制关闭、关闭后 lane 与 Chromium 子进程全部释放**，so that **长时间不用的会话不会耗光服务器内存或留下 Chromium 僵尸进程**。
11. As a **首版运维**，I want **WebSocket 握手与每条命令都校验当前用户身份，只能控制自己的会话**，so that **A 用户不能通过猜测 sessionId 控制 B 用户的浏览器**。
12. As a **M3 接手人**，I want **M2 的 `ExtractionPreview` 实现已经是 `PageExtractor` 的同一套提取逻辑**，so that **M3 接入运行调度时不需要为预览与运行维护两套代码**。
13. As a **M6 接手人**，I want **M2 的 `TargetUrlPolicy` 已经存在并覆盖所有入口 URL 校验，但只做 scheme + 主机名语法（不做 SSRF）**，so that **M6 替换为完整 SSRF 校验时只需要替换实现，不需要改调用点**。
14. As a **首版审计员**，I want **M2 的技术日志不包含页面内容、提取结果值、Cookie 或密码**，so that **M1 已经接好的日志脱敏正则继续生效**。
15. As a **前端开发者**，I want **`@visualspider/contracts` 包提供 M2 REST + WebSocket 的 TypeScript 类型，由 OpenAPI / 协议 schema 自动生成**，so that **我不手工同步类型，前后端契约错误在编译期就暴露**。

## Implementation Decisions

### D1. `visualbrowser` 模块结构升级

把 M0 spike 18 个生产类从 `com.visualspider.visualbrowser.*` 包顶层迁入：

```
com.visualspider.visualbrowser
├── spi/                         # 公开 stable interface (ADR-0003 seam)
│   ├── VisualSessionManager.java    # open/get/close/heartbeat/handleCommand
│   ├── LanePool.java            # 抽象 lane 池 (M2: ConfigLanePool 实现)
│   ├── FrameSink.java           # 帧消费者抽象 (用于测试 adapter)
│   └── TargetUrlPolicy.java     # 入口 URL 策略 (M2: scheme + host; M6: full SSRF)
├── internal/                    # 实现, 包级私有
│   ├── ConfigLanePool.java      # 固定 3 lane
│   ├── PlaywrightVisualSessionAdapter.java   # 生产 adapter, 包装 spike 类
│   ├── SystemLocatorGenerator.java           # 升级自 CandidateGenerator
│   ├── CleaningPipeline.java
│   ├── FrameSenderExecutor.java             # frameSenders 池 + @PreDestroy
│   ├── SessionLifecycleTicker.java          # 15min 空闲 / 2h 最长 计时
│   ├── SelectModeHandler.java
│   ├── BrowseModeHandler.java
│   └── ... (M0 spike 18 类迁入, package-private)
└── api/                         # REST + WebSocket 入口 (Controller)
    └── VisualSessionController.java
```

迁移原则：

- 行为零变化：M0 spike 12 个测试原样保留，断言与 fixture 不动（与 M0.5 spec 退出标准一致）。
- 18 个类**仅改包名**，不改逻辑。`VisualBrowserEndpoint` / `WebSocketConfig` 重命名为 `VisualSessionController` / `WebSocketConfig`，前者迁入 `internal/`（实现细节），后者保留在 `api/`（配置）。
- `package-info.java` 顶部注明"仅通过 `spi/` 对外暴露；`internal/` 包级私有不跨模块引用"。
- M1 spec 退出标准里"任何 `@Disabled` 测试遗留不允许"原则继承：M0 spike 已有的 `ScreencastFrameProducerIT` 维持 `@Disabled`，M2 不新增 `@Disabled`。

### D2. `VisualSessionManager` interface 草案

```java
public interface VisualSessionManager {
    /** 打开会话并绑定到 taskId; 仅任务所有者或 admin 可调用。 */
    VisualSession open(long taskId, ActorId actor);
    /** 获取当前用户在该 taskId 上的会话（每用户每任务 1 会话, 全局每用户 1 会话）。 */
    Optional<VisualSession> get(long taskId, ActorId actor);
    /** 心跳：空闲计时器重置。 */
    void heartbeat(String sessionId, ActorId actor);
    /** 关闭会话并释放 lane。 */
    void close(String sessionId, ActorId actor, CloseReason reason);
    /** 处理浏览/选择命令（由 WebSocket handler 调用）。 */
    void handleCommand(String sessionId, InputCommand command, ActorId actor);
}

public record VisualSession(
    String sessionId,
    long taskId,
    ActorId owner,
    Instant openedAt,
    Instant lastActivityAt,
    SessionLifecycleState lifecycle   // ACTIVE / IDLE_CLOSING / MAX_REACHED_CLOSING / CLOSED
) {}
```

`VisualSession` 是不可变 record；状态变化通过 `lifecycle` 字段更新，**不**修改现有 `VisualSession`（保留 spike 类的运行时可变模型在 `internal/` 包内）。

### D3. `ConfigLanePool` 与 lane 生命周期

```java
public final class ConfigLanePool implements LanePool {
    private static final int CAPACITY = 3;
    private static final Duration IDLE_LIMIT = Duration.ofMinutes(15);
    private static final Duration MAX_DURATION = Duration.ofHours(2);

    private final List<BrowserLane> lanes;  // 固定 3, 启动时初始化
    private final Semaphore available = new Semaphore(CAPACITY);

    public Lease acquire(ActorId actor) throws LaneUnavailableException;
    public void release(Lease lease);
}
```

- lane 在启动时初始化（`ApplicationRunner`），单例；3 个 lane 持有各自独立的 Playwright 实例。
- 借用通过 `Semaphore` 控制；超额借出抛 `LaneUnavailableException`（M2 阶段仅返回错误码
  `CONFIG_LANE_FULL`，不排队）。
- 关闭顺序：`Page.close()` → `BrowserContext.close()` → `Browser.close()` →
  `Playwright.close()`，全部在同一 lane 线程上串行（spike §4.1）。
- `SessionLifecycleTicker` 每 60 秒扫描所有 session：
  - `Instant.now() - lastActivityAt > IDLE_LIMIT` → 触发 `close(reason=IDLE_TIMEOUT)`。
  - `Instant.now() - openedAt > MAX_DURATION` → 触发 `close(reason=MAX_DURATION)`。
- 关闭事件写日志（DEBUG 级别，含 sessionId + reason，不含 owner 用户名以减少敏感信息）。

### D4. WebSocket 身份握手 + 每条命令校验

`WebSocketConfig` 升级：

```java
@Override
public void registerHandshakeHandlers(HandshakeInterceptor... interceptors) {
    interceptors.add(new SessionOwnerHandshakeInterceptor(
        identityAccess,
        csrfTokenRepository
    ));
}

@Component
final class SessionOwnerHandshakeInterceptor implements HandshakeInterceptor {
    @Override
    public boolean beforeHandshake(ServerHttpRequest req, ServerHttpResponse resp,
                                   WebSocketHandler wsHandler, Map<String, Object> attrs) {
        // 1. 读取 JSESSIONID cookie, 验证未过期
        // 2. 读取 query ?taskId= 与 URL path 中的 sessionId
        // 3. 检查 identityAccess.canAccessTask(taskOwnerId, currentActor)
        // 4. 读取 query `?csrf=` 与 XSRF-TOKEN cookie，校验一致；同时校验同源 Origin
        // 5. attrs.put("actorId", actorId); attrs.put("taskId", taskId);
        return true;  // 全部通过
    }
}
```

`VisualSessionController.handleTextMessage()` 入口：

```java
public void handleTextMessage(WebSocketSession ws, TextMessage msg) {
    ActorId actor = (ActorId) ws.getAttributes().get("actorId");
    Long taskId = (Long) ws.getAttributes().get("taskId");
    InputCommand cmd = parseAndValidate(msg.getPayload());  // 版本化 schema 校验
    sessionApi.handleCommand((String) ws.getAttributes().get("sessionId"), cmd, actor);

```

- 每条命令都重新校验 actor 与 taskId 所有权，不依赖前端隐藏。
- 拒绝越界坐标 / 过期 sessionId / 模式不匹配命令（spike §4.3 已实现，M2 把规则接到 sessionApi）。
- 帧丢弃策略：spike §4.3 的"帧通道只保留最新待发送帧，慢客户端时丢弃旧帧"由 `FrameBuffer`

### D5. `SystemLocatorGenerator` 与候选生成

升级自 `CandidateGenerator`：

```java
public final class SystemLocatorGenerator {
    /** 生成 N 个候选, 按稳定性评分降序。第一个是"最优"。 */
    public List<LocatorCandidate> generate(ElementSnapshot element, DomContext ctx) { ... }

    public record LocatorCandidate(
        String css,             // 合法 CSS 选择器
        String xpath,           // 合法 XPath
        int specificityScore,   // 0-100
        int stabilityScore,     // 0-100 (id > unique class > nth-of-type)
        int matchCount          // 在 ctx 中实测匹配数
    ) {}
}
```

稳定性评分规则：

- 元素有 `id` 且文档内唯一 → 100。
- 元素有 `class`，组合后唯一 → 80。
- 元素可由 `nth-of-type` + 父结构唯一 → 60。
- 仅有 `tag` 或仅 `:nth-child(n)` → 40。
- 文本内容作为选择器部分（M2 不引入，避免运行时依赖）。

生成时同步返回 CSS + XPath 两套；前端默认展示最优的 CSS，"查看候选"按钮展开列表。

### D6. `FieldDefinition` M2 扩展

```java
public record FieldDefinition(
    String name,                       // 已有: 非空, 不区分大小写唯一
    FieldSource source,                // M2: VISIBLE_TEXT / ATTRIBUTE / LINK_URL / IMAGE_URL / PAGE_URL
    String selector,                   // M2: 启用; 语法由 TaskReadiness 校验
    String attributeName,              // M2: source=ATTRIBUTE 时必填; 其他可空
    ResultType resultType,             // 已有: TEXT / NUMBER / URL (M2 全部启用)
    TrimPolicy trim,                   // 已有: TRIM / PRESERVE (M2 启用)
    String regex,                      // M2: 启用; capture group 替换策略见 D7
    boolean required                   // M2: 启用; 缺失诊断见 D8
) {}

public enum FieldSource {
    VISIBLE_TEXT,    // element.textContent
    ATTRIBUTE,       // element.getAttribute(attributeName)
    LINK_URL,        // element.getAttribute("href") 绝对化
    IMAGE_URL,       // element.getAttribute("src") 绝对化
    PAGE_URL         // 当前 page.url(), selector 与 attributeName 忽略
}
```

`PAGE_URL` 字段：selector 与 attributeName 强制 null/空；保存时 `TaskReadiness` 跳过 selector 语法校验。

### D7. `CleaningPipeline`

```java
public final class CleaningPipeline {
    public CleanedValue clean(String rawValue, FieldDefinition field) {
        // 1. trim: TRIM → strip; PRESERVE → 不动
        // 2. regex: 有 regex → Pattern.compile(regex).matcher(value);
        //    策略: 取第一个 capture group (group 1); 无 group 则取整体匹配 (group 0);
        //    全部不匹配 → null, 诊断 REGEX_NO_MATCH (rawValue 保留)
        // 3. type convert:
        //    TEXT → 原值
        //    NUMBER → new BigDecimal(strippedValue); 失败 → 原值 + TYPE_CONVERSION_FAILED
        //    URL → URI.create; scheme ∈ {http,https} 校验; 失败 → 原值 + TYPE_CONVERSION_FAILED
        // 4. empty: 空字符串或 null → null, 诊断 FIELD_EMPTY (rawValue 保留)
    }
}
```

### D8. 字段诊断

`ExtractionDiagnostic`（`extraction` 模块）：

```java
public record ExtractionDiagnostic(
    String fieldName,
    DiagnosticCode code,        // SELECTOR_SYNTAX_INVALID / ZERO_MATCH / MULTIPLE_MATCH
                                // / REGEX_NO_MATCH / TYPE_CONVERSION_FAILED
                                // / ATTRIBUTE_MISSING / FIELD_EMPTY
    String message,             // 用户可读
    String detailPath           // 可选: 错误位置 (selector 第几字符等)
) {}
```

- `SELECTOR_SYNTAX_INVALID`：保存时 `TaskReadiness` 返回 → status 回退 `DRAFT`；session 内
  实时反馈也返回同一诊断。
- `ZERO_MATCH` / `MULTIPLE_MATCH` / `REGEX_NO_MATCH` / `TYPE_CONVERSION_FAILED` /
  `ATTRIBUTE_MISSING` / `FIELD_EMPTY`：session 内实时 + 预览时返回，**不**影响
  `status`。
- 预览管道不修改数据库；只通过 `ExtractionPreview.preview()` 返回 `PreviewResult`（含
  fields、rawValues、cleanedValues、diagnostics）。

### D9. `TaskReadiness` M2 实现

按 [ADR-0005](./adr/0005-task-readiness-is-syntax-only.md)：

```java
public final class TaskReadinessImpl implements TaskReadiness {
    public ReadinessReport validateForRun(long taskId, ActorId actor) {
        TaskDraft draft = catalog.read(taskId, actor);  // 已做所有权校验
        List<ReadinessError> errors = new ArrayList<>();

        // 1. schemaVersion
        if (draft.definition().schemaVersion() != 1)
            errors.add(new ReadinessError("TASK_UNSUPPORTED_SCHEMA", "schemaVersion 必须为 1"));

        // 2. startUrl
        try {
            URI uri = URI.create(draft.definition().startUrl());
            String scheme = uri.getScheme();
            if (scheme == null || !(scheme.equals("http") || scheme.equals("https")))
                errors.add(new ReadinessError("TASK_INVALID_URL", "仅支持 http/https"));
            else if (uri.getHost() == null || uri.getHost().isBlank())
                errors.add(new ReadinessError("TASK_INVALID_URL", "主机名不能为空"));
            else if (!isValidHostSyntax(uri.getHost()))
                errors.add(new ReadinessError("TASK_INVALID_URL", "主机名语法不合法"));
        } catch (IllegalArgumentException e) {
            errors.add(new ReadinessError("TASK_INVALID_URL", e.getMessage()));
        }

        // 3. viewport
        if (!draft.definition().viewport().equals(new Viewport(1280, 720)))
            errors.add(new ReadinessError("TASK_INVALID_VIEWPORT", "viewport 必须为 1280x720"));

        // 4. fields
        if (draft.definition().fields().isEmpty())
            errors.add(new ReadinessError("TASK_NO_FIELDS", "至少 1 个字段"));
        Set<String> names = new HashSet<>();
        for (FieldDefinition f : draft.definition().fields()) {
            if (!names.add(f.name().toLowerCase(Locale.ROOT)))
                errors.add(new ReadinessError("TASK_DUPLICATE_FIELD", "字段名重复: " + f.name()));
            if (f.source() != FieldSource.PAGE_URL) {
                if (!isValidCssOrXPath(f.selector()))
                    errors.add(new ReadinessError("TASK_INVALID_SELECTOR", "选择器语法错误"));
            }
            if (f.source() == FieldSource.ATTRIBUTE && (f.attributeName() == null || f.attributeName().isBlank()))
                errors.add(new ReadinessError("TASK_MISSING_ATTRIBUTE_NAME", "ATTRIBUTE 字段必须指定属性名"));
        }

        return errors.isEmpty()
            ? ReadinessReport.ready()
            : ReadinessReport.draft(errors);
    }
}
```

CSS / XPath 语法校验：

- CSS：使用 `org.jsoup.select.Selector` 试解析，捕获异常。
- XPath：使用 JDK `javax.xml.xpath.XPathFactory.newInstance().newXPath().compile(xpath)`，
  捕获异常。
- 这两个步骤只做语法检查，不实际查询 DOM（运行时检查由 session 内实时反馈或预览完成）。

### D10. `EditingBuffer` 与自动保存

`visualbrowser` 模块内的 session-scoped 状态：

```java
public final class EditingBuffer {
    private volatile TaskDefinition current;     // 当前编辑中定义
    private volatile long baseVersion;          // 加载时的 task.version
    private final AtomicLong lastChangeAt = new AtomicLong(System.currentTimeMillis());
    private final ScheduledExecutorService saver;  // 单线程, session-scoped

    public void scheduleSave(Duration debounce);  // 5s 后 saveDraft
    public void flushSync();  // session 关闭前同步最后保存
}
```

- session 打开时加载 `task` 草稿到 buffer（`baseVersion = task.version`）。
- 字段/选择器修改 → `current` 更新 + `lastChangeAt` 更新 + `scheduleSave(5s)`。
- `scheduleSave` 用 `ScheduledExecutorService.schedule`：5s 后调用
  `TaskCatalog.saveDraft(taskId, current, baseVersion + 1, actor)`（注意 baseVersion 在保存
  成功后更新）。
- 乐观锁冲突：`saveDraft` 抛 `StaleTaskVersionException` → 重新读取 task 拿到新
  `baseVersion` → 合并 buffer（用户当前编辑优先于远端版本）→ 重试 1 次；仍冲突 →
  `EditingBuffer.conflict()` 返回给前端，要求用户手动保存或丢弃本地修改。
- session 关闭前 `flushSync()`：取消 pending schedule，立即同步保存一次；DB 不可用 →
  记录到 `logs/unsaved-buffer-${sessionId}.json` 仅作事故诊断，不写入 `run_result`。
- session 内编辑**不**触发 `TaskReadiness.validateForRun` 与 `status` 更新；只有
  `saveDraft` 成功后由 controller 调用 `validateForRun` 决定 `status`。

### D11. `ExtractionPreview` 与运行共用同一实现

```java
public interface ExtractionPreview {
    PreviewResult preview(TaskDefinition definition, DomState domState);
}
```

`PreviewResult`：

```java
public record PreviewResult(
    List<FieldOutcome> fieldOutcomes,
    List<ExtractionDiagnostic> diagnostics
) {
    public record FieldOutcome(
        String fieldName,
        String rawValue,        // 原始文本, ATTRIBUTE 时是 attribute 原始值
        String cleanedValue,    // CleaningPipeline 输出, 转换失败时仍为原始文本
        boolean isEmpty         // final 为 null/空

}
```

实现：

```java
@Component
public final class ExtractionPreviewImpl implements ExtractionPreview {
    private final CleaningPipeline cleaner;

    @Override
    public PreviewResult preview(TaskDefinition def, DomState domState) {
        List<FieldOutcome> outcomes = new ArrayList<>();
        List<ExtractionDiagnostic> diagnostics = new ArrayList<>();
        for (FieldDefinition field : def.fields()) {
            // 1. 在 domState 上跑 selector (M2: 单页, 没有 listItem 上下文)
            //    selector 语法无效 → SELECTOR_SYNTAX_INVALID
            //    0 匹配 → ZERO_MATCH
            //    多匹配 → MULTIPLE_MATCH, 取第一个
            // 2. 取原始值
            //    VISIBLE_TEXT → element.textContent
            //    ATTRIBUTE → element.getAttribute(attributeName); 缺失 → ATTRIBUTE_MISSING
            //    LINK_URL / IMAGE_URL → element.getAttribute("href"|"src") + 绝对化
            //    PAGE_URL → domState.url()
            // 3. CleaningPipeline.clean(rawValue, field) → finalValue + 诊断
            // 4. 拼 FieldOutcome
        }
        return new PreviewResult(outcomes, diagnostics);
    }
}
```

M3 引入 `run` 模块时，`RunCoordinator` 通过同一 `ExtractionPreview` 接口调用（保留实现
注入），保证"预览能用、运行失败"的不可能。

## Further Notes

- **M2 与 M0.5/M1 的 seam**：M0.5 迁入的 18 个 spike 类在 M2 二次迁移到 `spi/` /
  `internal/`，行为零变化（与 m0.5 spec 退出标准一致），不修改逻辑。M1 三个模块的接口形状
  在 M2 不变；M2 新增能力通过新接口实现。
- **M2 与 M0 spike 的 seam**：spike 决策门结论（screencast→screenshot / 一 lane 一浏览器 /
  全局≤3 / 4GB+4 核）原样保留；M2 决策 1 把"3 lane"明确为 config 独立池，与 spike §4.3 一致。
- **M2 → M3 的契约**：`ExtractionPreview` 已是 preview 与 run 共用接口；M3 `RunCoordinator`
  注入同一实现。`TaskReadiness.validateForRun` M2 接实现；`TaskSnapshotFactory` M1 占位
  → M3 接实现。`collection_run` / `run_result` / `run_event` 表 M3 启用（M2 不建表）。
- **M2 → M6 的契约**：`TargetUrlPolicy` M2 接 BasicTargetUrlPolicy；M6 替换为完整 SSRF
  实现，调用点不变。`ConfigLanePool` 容量常量 M6 写 DB。
- **诚实标注**：M2 spec 在 Linux smoke 段落写明「Linux smoke: not executed in M2; see M7」，
  符合 AGENTS "本地缺少 PostgreSQL/Chromium 时要明确列出未运行的验证，不能静默跳过后宣称
  全部通过"。
- **与 AGENTS "每个里程碑退出标准有可复现证据"**：M2 退出标准 7 条（roadmap §6）由 issue
  (e) 的 `m2-smoke.ps1` 一一对应：① 用户可从 URL 打开公开静态页 / JS 动态页 → step 5-6；
  ② 配置会话 15min / 2h 关停 → `IdleCloseIT` + step 12-13；③ 浏览模式不创建规则 / 选择
  模式不触发原页面动作 → `BrowseModeIT` + `SelectModeIT`；④ 系统规则与手写 CSS/XPath 一致
  → `AdvancedSelectorEditorIT`；⑤ 字段多匹配 / 缺失 / 正则失败 / 类型失败诊断 →
  `PreviewIT` + `TypeConversionIT`；⑥ 修改入口 URL / 失效规则 → DRAFT → `TaskReadinessIT`；
  ⑦ 预览与保存通过权限 + SSRF 基础 → `SessionLifecycleIT` + step 6-9。
- **与 ADR-0003**：`visualbrowser` 模块在 M2 首次落地稳定 `spi/` interface；`internal/`
  包级私有不跨模块引用。M3/M4 接入新模块时如果需要新增 interface，应在 ADR 体系内追加
  "模块边界第三阶段" 记录。
- **与 ADR-0004 / ADR-0005**：本 spec 是这两个 ADR 的实施落地；任何 M2 代码违反这两个
  ADR 时由 PR review 阻断。
- **乐观锁冲突 UX**：`EditingBuffer.conflict()` 不弹 modal；改为在 session UI 顶部显示
  红色 banner「任务已被另一端点修改，请刷新或合并本地修改」，提供"放弃本地" /
  "覆盖远端"两个按钮。避免打断用户输入流。
- **`PAGE_URL` 字段**：保留为隐式字段（selector/attributeName 强制空）；M4 引入列表后
  `PAGE_URL` 仍可用，作为"列表页 URL"补充字段。
- **CleaningPipeline 与运行共用**：M3 运行提取每条记录时也走 `CleaningPipeline`；不在
  run 模块重复实现。M3 spec 落地时显式引用本 spec 的 D7。
- **可视化产品化的边界**：M2 的"配置体验"是首版最重要的用户感知，必须以"实时反馈 +
  明确诊断 + 不丢数据"为体验基线。M3+ 任何破坏这三点的变更需要重新 grilling。
