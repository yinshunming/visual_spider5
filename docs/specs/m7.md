## Problem Statement

功能与加固已完备,但按 roadmap §7 边界,M0–M6 产物仍是"开发机上能跑":

- **没有可跟随的部署路径**:一名部署者拿到 JAR 后,没有任何文档告诉他装什么、放哪里、怎么配置、怎么启动和停止;Windows/Linux 均如此。
- **Linux 从未真实验证**:所有 IT 和 smoke 都在 Windows 上执行;Linux 的浏览器依赖、进程回收、systemd 行为是未知数(M0 明确延后的项)。
- **升级与数据安全无剧本**:首版之后必然有补丁,但备份、恢复、Flyway 前滚、失败回滚没有任何文档和演练;一次失败的 migration 就可能让部署者丢数据。
- **验收清单无证据**:product-spec §13 的 13 条验收项目前散落在各里程碑测试里,没有一份逐项可复现的证据汇总。
- **没有版本锚点**:`0.0.1-SNAPSHOT` 无法支撑发布说明、升级路径和后续补丁的引用。

## User Stories

1. As a **部署者**,I want **一份从裸 Windows/Linux 到可登录的跟随式安装文档**,so that **我不需要了解这个仓库的开发结构就能把首版装起来**。
2. As a **部署者**,I want **start/stop/status/logs 运维脚本与 PID/日志文件约定**,so that **日常运维有固定入口,不用手敲 java 命令**。
3. As a **部署者(Linux)**,I want **systemd unit 管理进程**,so that **崩溃自动重启、开机自启、`journalctl`/`systemctl` 语义可用**。
4. As a **部署者**,I want **备份、恢复、升级、失败回滚各有明确步骤**,so that **打补丁时知道怎么做才不丢数据**。
5. As a **部署者**,I want **配置参考列出全部环境变量、合法值和日志位置**,so that **除初始管理员外不需要读代码就能配**。
6. As a **管理员**,I want **首版有一个版本号和发布说明**,so that **后续升级和问题报告有共同引用锚点**。
7. As a **首版采集人员**,I want **在局域网另一台电脑上远程配置会话点击/滚动的反馈在半秒左右**,so that **点选字段不至于痛苦**(M0 延后验收)。
8. As a **发布审计员**,I want **product-spec §13 每条验收项对应到自动化测试或可重复手工证据**,so that **"首版完成"是证据链而非口头判断**。
9. As a **发布审计员**,I want **发布包/发布产物检查确认无密钥、开发数据库凭据和测试用户密码**,so that **交付物本身不泄密**。
10. As a **首版后接手人**,I want **已知限制(含 SSRF 残余风险、单实例、HTTP)集中在 release-notes**,so that **后续规划不需要从代码考古里挖边界**。

## Implementation Decisions

### D1. 部署布局与运行账户

**Windows**:

- 目录 `C:\visual-spider\`:`app.jar` + `config\`(可选外部 `application.yml` 覆盖)+ `logs\`。
- JDK:Eclipse Temurin 21 LTS(官方安装包);PostgreSQL 16(EDB 安装器);运行账户:部署者本人的常规账户(不建专用账户,Windows 私有部署场景下成本大于收益)。
- **不注册 Windows 服务**:start/stop/status 用脚本 + PID 文件 + `/actuator/health`(与 e2e smoke 启停模式一致);开机自启首版不承诺(进已知限制)。

**Linux**:

- 专用系统用户 `visualspider`(无登录 shell);目录 `/opt/visual-spider/`:`app.jar` + `config/`(`visual-spider.env` 环境文件 + 可选 `application.yml`)+ `logs/`。
- JDK:Temurin 21(apt 源或 tar.gz);PostgreSQL 16(pgdg apt);Ubuntu Server 24.04 LTS **单目标**(Debian 12 一句话说明"大概率可用但不承诺、不验收")。
- systemd unit `/etc/systemd/system/visual-spider.service`:`User=visualspider`、`Restart=on-failure`、`EnvironmentFile=/opt/visual-spider/config/visual-spider.env`、`ExecStart=java -jar /opt/visual-spider/app.jar`;不用 systemd 时 `start.sh`/`stop.sh` 直接可用(两条路径都验收:systemd 为主,脚本为回退)。
- Chromium 装在 `visualspider` 用户的 `~/.cache/ms-playwright`(Playwright 默认位置;如用 systemd `User=` 指向该用户则路径自然正确)。

### D2. 运维脚本集职责(两平台对称)

`install.ps1/sh`(JDK/PG 存在性检查提示、`playwright CLI install chromium`、Linux 加 `install-deps`、打印实际 Chromium revision)、`check-env.ps1/sh`(JDK 版本、PG 连通、端口占用、磁盘空间)、`start` / `stop` / `status` / `logs`。

- `start`:后台启动,PID 写 `logs/app.pid`,stdout/stderr 重定向到 `logs/app.out.log`/`app.err.log`,启动后读最近日志确认(沿用全局 CLAUDE 长期服务规则)。
- `stop`:按 PID 优雅停止,超时强杀;`status`:查 PID 存活 + `/actuator/health`;`logs`:tail 两个日志文件。
- 脚本是**部署资产**:只依赖 JAR 与运行时,不依赖仓库源码(与 `scripts/e2e/*` 开发脚本分离)。
- 参数化 JAR 名与路径(不做第二个硬编码 jar 名的出处,M7-6 定版时一并清理)。

### D3. Chromium 安装与版本记录

- 安装命令:`java -cp app.jar com.microsoft.playwright.CLI install chromium`(Linux 先 `install-deps`);由 `install` 脚本执行,不要求部署者手敲。
- 版本锁定表记"Playwright 1.61.0 -> 其捆绑的 Chromium revision";**revision 号由 install 脚本安装时实际打印并写入部署记录**(`logs/` 下安装日志),不手工抄进文档,避免文档漂移。

### D4. `configuration.md` 内容与 README 澄清

- 环境变量全表:`VISUALSPIDER_DATASOURCE_URL/USERNAME/PASSWORD`、`VISUALSPIDER_ADMIN_USERNAME/PASSWORD`(仅首启 seed)、`VISUALSPIDER_FLYWAY_ENABLED`、`SERVER_PORT`;`retention.days` 经 admin REST 调整(非环境变量,指向 M6-6 接口)。
- 日志位置与轮转(logback-spring.xml 现状)、健康端点、`visualbrowser.target-url.allow-loopback` **仅测试用途**的警告(沿用 M6 D4 措辞:生产开启等于放弃回环防护)。
- actuator 暴露现状与决策:**保持 health,info 为生产默认**(零代码改动);`/actuator/metrics` 的开启方式以配置示例写进文档(排障场景自行打开,不开不丢指标——指标仍在 MeterRegistry/内部计数,属观测便利性而非功能)。若发布检查发现必须默认可查再单开 bug,不在本 spec 预设改动。
- 版本锁表从 README 迁移到本文档,README 保留概览 + 指向 `docs/deploy/` 的入口节。
- **README 反代表述澄清**:删去/改写"生产部署请在反向代理层终止 TLS"一句——首版交付物是单 JAR 直接提供 HTTP,反向代理 TLS 属首版后候选(roadmap §12),文档不得暗示它是首版部署方式。

### D5. 备份/恢复/升级流程(`backup-restore-upgrade.md`)

- 备份:`pg_dump -Fc` 全库逻辑备份(给出命令、频次建议、备份文件保管);恢复:`pg_restore` 到新库 + 应用侧改连接串。
- 升级:`pg_dump` 备份 -> 停应用 -> 替换 JAR -> 启动(Flyway 自动前滚)-> 冒烟(登录 + 单页采集)。
- 失败回滚:恢复备份库 + 回退旧 JAR;说明 Flyway 已应用版本与 baseline 的关系(`baseline-on-migrate` 现状、历史库前滚的注意事项,引用 memory 中"baseline-on-migrate 旧表陷阱"的教训)。
- 演练(M7-3 内执行):从 M6 收口构建 + 其数据库出发走完整升级;再人为制造一次前滚失败(如损坏的 SQL/中断),走恢复备份路径。

### D6. `m7-acceptance` 脚本形态

- 参数化 `BaseUrl`、JAR 路径、fixture 端口;**脚本自管 JAR 启动**(与 m2–m6 smoke 同模式):显式 `--visualbrowser.target-url.allow-loopback=true`(验收模式,文档与脚本注释均标注"仅测试"),fixture server 用 `python -m http.server`(Python 是验收脚本的前置依赖,写进文档;非生产运行时依赖)。
- 链路步骤:admin 登录 -> 创建 collector 账号 -> collector 登录 -> 单页任务(配置/预览/运行/导出)-> 列表 -> 翻页 -> 加载更多 -> 内容页 -> 取消运行 -> 导出 CSV/JSON 行数校验 -> retention 触发。权限负向检查(跨用户 403/404)穿插。
- 已部署实例本身的验收(安装文档可跟随性)归 M7-1/M7-2 的演练清单,不在本脚本重复。
- **修复既有 smoke**:m2–m6 smoke 补显式 `allow-loopback=true` 参数,消除 M6 SSRF 合入后的疑似破坏(先复现确认,再最小修复)。
- `.sh` 首次实装并在 Linux 真实执行。

### D7. LAN 延迟采样 + Linux 资源回收(M0 延后项)

- 延迟:第二台 PC(同一 LAN)浏览器 console 运行采样脚本(粘贴式,测点击/滚动命令发出到下一帧到达的 RTT,利用既有帧序号/时间戳协议),各 20 次,取中位数;目标 ≤500ms。证据(数值输出)贴 m7.md。超标则按"性能问题"开 bug 评估,不静默放宽。
- Linux 资源回收:`m7-acceptance.sh` 收尾步骤核对运行前后 Chromium/Playwright Java 进程数,断言无遗留(Windows 侧 M6 已有同款核对,此次补 Linux)。

### D8. 发布检查清单 + release-notes

- 清单以 product-spec §13 的 13 条为行,列为"证据类型(自动化 IT / smoke / 手工演练)+ 证据位置(issue 编号/m7.md 节)";手工项注明复现命令。
- 发布包检查:JAR 与 docs 中无密钥、无开发数据库凭据、无测试用户密码(`git grep` 哨兵式核查 + 人工过目)。
- 已知限制(roadmap 点名五项):HTTP 明文(仅可信 LAN/VPN)、SSRF 残余风险(链接 ssrf-residual-risk.md)、不读取 robots.txt、单实例(advisory lock)、不支持登录态采集;另加:Windows 无开机自启、验收依赖 Python fixture server(非运行时)。

### D9. 定版(M7-6)

- pom `<version>` 改 `0.1.0`(去掉 SNAPSHOT);`mvn package` 产物名变为 `visual-spider5-0.1.0.jar`;**7 处硬编码 jar 名连带修改**(借机参数化,不新增第六处硬编码)。
- git tag `v0.1.0`(annotated,tag message 引 release-notes);README 部署入口节;roadmap M7 退出标准勾选、product-spec §13 完成态说明;`CONTEXT.md` 不动(M7 无新领域术语)。
- 定版后所有 smoke/acceptance 在 `0.1.0` 下重跑一遍作为 tag 前最后验证。

### D10. 横切

- **零业务代码改动原则**:M7 的改动仅限 ops 脚本、文档、pom 版本、e2e 测试脚本修复;演练/验收中发现的 bug 按阻断标准(D11)走独立 bug issue(复现 -> 回归测试 -> 最小修复 -> 验证),不混入发布工单。
- 零新 Maven/npm 依赖;零 Flyway migration;前端无改动。
- **阻断判定标准**(grilling 决策):主链路不可用、数据丢失/越权、升级或恢复路径断裂 = 阻断发布;UX 瑕疵、文档错字、非主链路边缘 bug = 记入 release-notes 已知限制。
- 敏感信息:文档示例一律占位符;演练产生的真实凭据不进 git。
- 文档同步:本 spec + `docs/deploy/` 五篇 + README + roadmap/product-spec 完成态。

### D11. 演练执行方式与诚实性

- Agent 产出脚本与文档;**用户在 VM/第二台 PC 上按文档人工执行**(复制/手敲),终端输出与截图贴回 issue 或 m7.md 作为证据——验收的本质是文档可跟随性,不由 agent 远程代跑。
- Windows 干净演练 = 全新 Windows 11 VM(Hyper-V);Linux = 全新 Ubuntu Server 24.04 VM;均留快照可重复。若 Windows 侧退化为"开发机半干净环境",必须在 m7.md 如实标注折扣。
- 本地缺环境未运行的验证,显式列入"未覆盖",不得静默宣称通过。

## Testing Decisions

### T1. 脚本自检(可自动化部分)

- 运维脚本:参数缺失/重复启动/未运行时 stop 等失败路径有明确报错退出码;`status` 在 PID 过期时报"未运行"而非误报。
- `m7-acceptance`:任一步骤失败即非 0 退出并指明步骤号;可重跑(清理上次数据或用独立任务名)。
