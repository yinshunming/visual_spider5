## What to build

T1 已铺好 `com.visualspider.*` 模块骨架与顶层 `Application`。本工单做 contract 步骤——把 M0 spike 18 个生产类（`SpikeApplication` 已在 T1 改名 `Application` 升顶层）与 14 个测试类**一对一**从 `com.visualspider.spike.m0.*` 搬到 `com.visualspider.visualbrowser.*`，完成全仓库命名清理。

具体落点：

1. 生产类搬运（18 个，`SpikeApplication` 已在 T1 处理）：
   - `BrowserLane`、`CandidateGenerator`、`ElementSummary`、`FrameBuffer`、`FrameProducer`、`InputCommand`、`InputSequencer`、`PlaywrightControl`、`ScreencastFrameProducer`、`ScreenshotFrameProducer`、`SelectionRecord`、`StatusMessage`、`ValidationResult`、`ViewportMapper`、`VisualBrowserEndpoint`、`VisualSession`、`VisualSessionManager`、`WebSocketConfig`
   - 每个文件：`package com.visualspider.spike.m0;` → `package com.visualspider.visualbrowser;`
   - 文件内部所有 `import com.visualspider.spike.m0.*;` 改为 `import com.visualspider.visualbrowser.*;`
   - 类名、可见性、方法签名、Javadoc 一律不改
2. 测试类搬运（14 个，全在 `src/test/java/com/visualspider/spike/m0/`）：
   - 同样改 `package` 与 `import`
   - 不动测试断言、不动 fixture 路径、不动 `@Disabled`
3. 启动类引用更新：
   - T1 已建 `com.visualspider.Application`，无需 T2 改；但需要扫描是否还有其他文件 `@SpringBootApplication` 或 `SpringApplication.run(SpikeApplication.class, ...)` 残留引用
4. 清理 `com.visualspider.spike.m0` 空包（搬运完成后 `git ls-files` 应 0 命中）
5. 跑全量验收：见 Acceptance criteria

## Acceptance criteria

- [ ] `git ls-files src/main/java/com/visualspider/spike/m0/` 与 `git ls-files src/test/java/com/visualspider/spike/m0/` 均 0 命中。
- [ ] `git ls-files src/main/java/com/visualspider/visualbrowser/` 命中 18 个生产类（`SpikeApplication` 已升顶层，不在内）；`src/main/java/com/visualspider/Application.java` 单独存在。
- [ ] `git grep -l "com\.visualspider\.spike\.m0"` 全仓库（main / test / pom / docs）0 命中。
- [ ] `./mvnw clean verify` 全绿（14 个测试全过，行为与重构前等价）。
- [ ] `./mvnw clean package` 产出可执行 JAR；`java -jar` 启动成功（不依赖 DB）。
- [ ] `git diff --stat HEAD~1..HEAD -- 'src/main/java/com/visualspider/visualbrowser/*.java'` 显示 18 个文件状态为 renamed + 仅 `package` / `import` 行改动；非测试生产类**无任何逻辑行变化**。
- [ ] `docs/roadmap.md` 新增 M0.5 章节（目标 / 范围 / 退出标准 / 不做项 / 建议 AI 工单）。

- [ ] 19 个生产类中**只有 `SpikeApplication` 改名 `Application`**，其余 18 个类名不变。
- [ ] 14 个测试类的 `@Disabled` 状态、断言、fixture 路径全部保持原样。

## Out of scope

- 不引入新依赖、不引入 Flyway / DB、不引入 ArchUnit、不引入 interface。
- 不修改 `pom.xml`（依赖 ID 不变）。
- 不修改任何类的内部逻辑行（仅 `package` / `import` 与启动类 Javadoc 同步）。
- 不重新启用 `ScreencastFrameProducerIT` 的 `@Disabled`——screencast 不可用是 M0 决策门遗留。
- 不写新测试、不重命名除 `SpikeApplication` 外的任何类。
- 不拆 Maven 子模块。
- 不移动 `src/test/resources/fixtures/`。
