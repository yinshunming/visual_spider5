#7 — M0.5: 按业务模块重排 M0 spike 代码

## What to build

按 ADR-0003 在仓库里建立 `com.visualspider.*` 模块包结构。**老 `com.visualspider.spike.m0.*` 19 个类一行不动**——本工单是 expand 步骤：先把新形式铺好，让老形式继续可用，CI 独立绿。

具体落点：

1. 建 7 个新包，每个挂 `package-info.java`：
   - `com.visualspider.visualbrowser`（实包雏形，仅含 `package-info.java`；19 个类暂不搬入，留给 T2）
   - `com.visualspider.identity`（占位）
   - `com.visualspider.task`（占位）
   - `com.visualspider.extraction`（占位）
   - `com.visualspider.run`（占位）
   - `com.visualspider.result`（占位）
   - `com.visualspider.shared`（占位）
2. `package-info.java` 模板（每个包替换模块名 / 里程碑）：
   ```java
   /**
    * <模块名> 模块。
    *
    * <p>本包承载 <模块名> 业务能力。
    * M<里程碑> 启用；M0.5 仅完成包结构占位。
    *
    * <p>本包遵守 ADR-0003（按业务模块组织深模块）：
    * 仅通过稳定 interface 对外暴露能力；隐藏数据库、Playwright、
    * 执行状态等实现细节。
    */
   package com.visualspider.<module>;
   ```
   模块与里程碑对应：`identity` → M1、`task` → M1/M2、`extraction` → M2/M3、`run` → M3、`result` → M3、`shared` → 跨里程碑（按 AGENTS "只放稳定标识符、时钟和小型错误类型"）。`visualbrowser` 包注明"由 M0 spike 升入，M0.5 完成包结构，M2 起产品化"。
3. 启动类升顶层：
   - 把 `SpikeApplication` 重命名为 `Application`，移到 `com.visualspider` 顶层包。
   - 类内 `SpringApplication.run(...)` 同步改为引用新类名。
   - 不动 `@SpringBootApplication` 注解——其默认扫描 `com.visualspider.*` 仍能覆盖现有 `spike.m0` 子树。
4. 老包 `com.visualspider.spike.m0` 内 18 个其他生产类与 14 个测试类**全部不动**。
