## 现状(M5 已合 main,本 spec 是叠加)

M5 已于 2026-08-21 合 main(`c35a41f`,issue #41-#45 全部关闭)。M6 不新增产品能力、不破 M1-M5 任何契约;所有改动是"收紧与加固"。现状调查(2026-08-23)确认的空白:

## 上游约束(M1-M5 已落地的契约与 seam)

- `TargetUrlPolicy` SPI(`visualbrowser.spi`)签名不变;5 处调用点(`LegacySessionFactory`、`SinglePageRunExecutor`、`ContentPageFetcher`、`ListRunExecutor`/`MultiPageRunExecutor` 装配)不改调用方式,M6 只换实现。
- 全部 pg-it fixture 由本地 `com.sun.net.httpserver` 以 `http://localhost`/`127.0.0.1` 伺服;SSRF 收紧后**必须**靠 test profile 豁免 loopback,否则 M1-M5 全部 IT 失效。
- `BrowserContext` 创建集中点:配置会话(`visualbrowser`)与采集运行(`run`)各自独立、非持久化;请求拦截在创建点一次性注册,Web/WS 线程不触碰 Playwright 对象(线程亲和约束不变)。
- WebSocket 容器缓冲(1MB 二进制/512KB 文本)为出帧 JPEG 服务,**不能**调小;入站限制必须在 handler 层实现。
- `RunLimits` SPI、`PacingPolicy`、`PageStopDetector`、`RetentionCleanup`、lane 容量等 7 处"M6 入 system_setting"预留点:M6 **只动 retention 一项**(见 D14),其余维持代码默认值,留 M7 配置参考。
- `BusinessErrorCode` 体系(M1 5 项 + M4/M5 扩展)不变;M6 不新增用户可见错误码。
- `run_event.message` 不含堆栈/页面内容/结果字段值的约定不变;`LoggingScrubber` 规则集是 LogSanityIT 的断言来源。
- Flyway 已应用 V1-V4;M6 **零 migration**(system_setting 用代码幂等 seed,不新增表/列)。
- 单 JVM 派发器 + lane 单线程亲和(ADR-0006)不变;崩溃重建发生在 lane 自己的线程内。

## Problem Statement

系统在功能上已完成首版范围(单页/列表/翻页/加载更多/一层内容页),但按 roadmap §7 的边界,M0-M5 产物只能跑在开发环境。直接给真实采集人员用会暴露:

- **SSRF 全面失守**:任何登录用户可以在任务里填 `http://127.0.0.1:*` 或内网地址,浏览器会真的去访问;重定向到云元数据地址也是加载完成后才失败;页面子资源(图片、脚本、XHR)完全不受限。在可信内网部署时,这等于给内网/服务器元数据开了一个浏览器代理。
- **误开双实例会分裂调度**:文档说"禁止两个 JAR 连同一业务库",但没有任何机制阻止;第二个实例会各自派发、各自占 lane,产生双倍目标站点压力和状态覆盖写。
- **遗留 WS 端点裸奔**:`/ws/visual` 无身份、无所有权、无 CSRF 校验,任何能到达端口的人可以开浏览器会话。
- **浏览器一崩全崩**:Chromium 崩溃或 Playwright 连接断开后,该 lane 永久报废但仍在池中被借出,表现为"之后每次采集都莫名失败",需要重启整个 JAR。
- **容量从未验证**:3 并行、200 页、10k 结果、30 分钟这些写进约束的数字没有任何测试证据;慢 WS 客户端、大结果分页在负载下的行为未知。
- **审计无从下手**:没有指标、没有端到端日志干净性证据、保留天数写死无法调、权限回归靠 M1 时代的一次性测试。

## Solution

M6 落地 6 张 issue,**严格串行**(a -> b -> c -> d -> e -> f,不并行开工;与 M5 不同,无三阶段交叉):

- **(a) SSRF 完整防护 + 恶意 fixture 测试集 + 残余风险说明**(roadmap 工单 1+2 合并)
  - `PublicTargetUrlPolicy implements TargetUrlPolicy`:scheme + 主机名语法沿用,新增**DNS 解析全部结果**的 IP 分类校验(拒绝回环/私有/链路本地/保留/组播/云元数据;IPv4 + IPv6 + 混合表示)。
  - 请求拦截:`BrowserContext` 创建点注册 `context.route("**/*")`,拦截时解析并校验该请求 host 的全部 DNS 结果,不通过 `abort`,通过 `resume`;导航/重定向/子资源统一覆盖。
  - 内部 `DnsResolver` seam(生产 `InetAddress`、测试 fake)+ 30s TTL 缓存。
  - `visualbrowser.target-url.allow-loopback` 配置(默认 `false`);仅 `it`/`dev` profile 置 `true`,豁免范围仅 loopback(`127.0.0.1`、`[::1]`),不豁免任何其他私有网段。
  - 导航后 `currentUrl()` 复验保留(纵深防御,不删)。
  - 恶意 fixture 目录(`ssrf/`):重定向到 loopback、子资源引 loopback/元数据地址、混合表示 IP(如 `127.1`)等;`docs/security/ssrf-residual-risk.md` 记录 TOCTOU 残余窗口 + 主机防火墙建议。
  - Acceptance:直接 URL、重定向、子资源三类 fixture 均无法访问非公网地址;全部 M1-M5 IT 在 loopback 豁免下保持绿。

- **(b) 单实例 advisory lock(ADR-0007)**
  - `run` 模块 internal `SingleInstanceGuard`:启动早期(SmartLifecycle 最先 phase)用**专用 JDBC 连接**(不进 HikariCP 池)执行 `pg_advisory_lock(固定 key)`,拿不到锁立即抛异常终止启动,日志给出明确指引;关闭时释放。
  - 锁 key 用稳定常量;连接断开锁自动释放(崩溃残留自愈,无需 TTL/清理)。
  - Acceptance:pg-it 中预占锁再启动 Spring context 断言失败退出;正常启动/关闭循环不残留。

- **(c) WebSocket 加固 + legacy 端点删除**
  - 删除 `/ws/visual` 端点与 `VisualBrowserEndpoint`(前端零引用,已核实)。
  - `InboundGuard` decorator(`WebSocketHandlerDecoratorFactory` 统一挂到全部 WS handler):入站二进制一律断连;入站文本 > 8KB 断连;每连接 20 msg/s 滑动窗口,持续超限(3 秒窗口内持续超)断连并记 WARN(不含消息内容)。
  - 出站帧通道(FrameBuffer 丢旧单帧槽)不动;`InputSequencer` 防重放不动。
  - Acceptance:IT 用 WS 客户端验证超尺寸/二进制/速率超限各自被断连;正常交互不受影响。

- **(d) lane 崩溃检测与自动恢复 + health 真实化**
  - `BrowserLane` 识别崩溃特征(`TargetClosedException`、Playwright 连接断开的异常族),置 unhealthy 并在 **lane 自己的线程内**按关闭顺序回收旧对象、重建 Playwright+Browser,恢复 healthy 回池。
  - borrow 方语义:借出到崩溃 lane 的那次调用收到一次可重试失败(不重试机制新增,沿用各调用方现有失败路径);下一次 borrow 拿到已重建的 lane。
  - `BrowserHealthIndicator` 聚合两个池的真实 lane 健康状态;lane 线程名改 `browser-lane-N` 唯一。
  - 不做 OS 级进程扫描;僵尸进程防护 = 统一 close 路径(Playwright close 内部 kill)+ (e) 压测时的 PID/日志人工核对步骤。
  - Acceptance:真 Playwright IT 强杀 browser 后,下一次 lane 提交成功、health 从 DOWN 恢复 UP;无遗留 Playwright Java 进程。

- **(e) 并发/长列表/大结果压力测试 + RunLimits 收敛**
  - `RunDispatcher` 内联常量删除,上限唯一来源收敛到 `RunLimits` SPI。
  - 独立 IT profile(`pg-stress`,常规 `verify` 不跑):
    - 3 个真实 Playwright 运行并发打满 RunLanePool,期间并发断言登录、任务查询、结果分页可用且正确(可用性/正确性断言,不做硬性性能阈值);
    - DB 预插 10,000 行 `run_result` 验证分页查询与流式导出可用;
    - 200 页边界 fixture 验证 `PAGE_LIMIT` 停止。
  - 运行后遗留进程核对脚本/步骤写进 issue(PID 记录 + 进程数断言)。
  - Acceptance:3 并行期间 REST 全部可用;10k 分页/导出正常;200 页正确停止;无遗留进程证据留存。

- **(f) 日志/指标/清理/权限审计 + retention 入 system_setting**
  - micrometer 指标(6 项):`runs.active`(gauge)、`runs.started`/`runs.completed`(counter)、`lane.borrowFailed`/`lane.crashRebuild`(counter)、`ssrf.blocked`(counter)、`retention.deletedRows`(counter);`/actuator/metrics` 可查,不做前端面板。
  - `LogSanityIT`:一次覆盖登录 + 采集运行 + WS 会话的 IT 全程输出日志到临时文件,结束后扫描断言无密码/Cookie/XSRF-TOKEN/结果字段值/页面内容模式(复用 `LoggingScrubber` 正则集 + 结果值/页面文本抽样断言)。
  - 权限/停用回归矩阵 IT:admin 全局可见、collector 隔离、停用账号拒绝(即使 admin)三轴断言。
  - system_setting 仅 `retention.days`(默认 30):启动幂等 seed(`INSERT ... ON CONFLICT DO NOTHING`,修正 V1 注释与实际的偏差),`RetentionCleanupTask` 读库、缺行 fallback 30;管理员 REST `GET`/`PUT /api/admin/settings/retention.days`(仅此 key,未知 key 404);前端 UI 不做(留 M7 文档/首版后)。
  - Acceptance:指标可查;LogSanityIT 绿;权限矩阵绿;改 `retention.days` 后清理按新值执行且重启不丢。

(a) 契约与安全边界(跨 visualbrowser/run);(b) 调度准入;(c) 通道加固;(d) 资源恢复;(e) 容量验证;(f) 可观测与收尾。

## User Stories

1. As a **部署者**,I want **直接 URL、重定向和页面子资源都无法访问回环/私有/元数据地址**,so that **我把系统部署在内网时不会给攻击者提供一个浏览器代理**。
2. As a **部署者**,I want **第二个 JAR 连接同一业务库时启动直接失败并给出明确报错**,so that **误开双实例不会分裂调度、双倍打目标站点或覆盖写状态**。
3. As a **部署者**,I want **Chromium 崩溃后 lane 自动重建并恢复服务**,so that **一次浏览器崩溃不需要重启整个 JAR,采集人员也不会遭遇连续莫名失败**。
4. As a **部署者**,I want **运行计数、lane 崩溃重建、SSRF 拦截、清理删除行数等指标可查**,so that **长期运行时我能用 `actuator` 判断系统是否健康、是否在被滥用**。
5. As a **管理员**,I want **通过 REST 读取和修改保留天数**,so that **不用改代码或直接操作数据库就能调整运行/结果的保留期**。
6. As a **管理员**,I want **停用账号立即失去全部访问(即使我本人也不例外)**,so that **人员离开团队后其账号不残留任何可用入口**。
7. As a **首版采集人员**,I want **任务里填内网地址时在保存/就绪阶段被拒绝并得到可理解的提示**,so that **我不会配置一个永远跑不出来的任务**。
8. As a **首版采集人员**,I want **3 个并行运行期间登录、查任务、翻结果分页依然可用**,so that **有人在跑大任务时我的日常操作不被卡死**。
9. As a **首版审计员**,I want **一次全链路运行后的日志文件被自动扫描并断言不含密码/Cookie/结果值/页面内容**,so that **"日志无敏感信息"这条验收有可复现证据而非口头承诺**。
10. As a **首版审计员**,I want **未知/越权的 WebSocket 消息(超尺寸、二进制、命令洪泛)被拒绝或断连**,so that **WS 通道不能被用来打爆内存或干扰他人的配置会话**。
11. As a **首版审计员**,I want **任何用户都无法通过 WS 订阅、控制或猜测他人的配置会话**,so that **采集人员之间的数据边界在实时通道上同样成立**。
12. As a **安全审计员**,I want **SSRF 恶意 fixture 测试集(IPv4/IPv6/混合表示/重定向/子资源/DNS 多记录)进仓库并持续运行**,so that **防护回归有 adversarial 证据,残余风险有明确文档**。
13. As a **安全审计员**,I want **DNS 变化竞态的能力边界和主机防火墙建议被明确记录**,so that **我能在部署评审时区分"已防护"与"接受残余风险"**。
14. As a **运维**,I want **200 页/10k 记录/3 并行容量有自动化测试证据,运行后无遗留浏览器进程**,so that **容量承诺和资源回收不是纸面数字**。
15. As a **M7 接手人**,I want **M6 的 SSRF 残余风险、单实例限制、HTTP-only 部署约束集中在文档中**,so that **发布说明的"已知限制"一节可以直接引用**。
16. As a **M7 接手人**,I want **`m6-smoke.ps1` 沿用 m2-m5 风格且 `.sh` 占位标注 Linux 留 M7**,so that **跨平台验收只补 Linux 真机执行**。

## Implementation Decisions

### D1. `PublicTargetUrlPolicy` 实现 + IP 分类

```java
final class PublicTargetUrlPolicy implements TargetUrlPolicy {
    // SPI 不变: validate(url) / isAllowed(url) 沿用 BasicTargetUrlPolicy 签名
    private final DnsResolver dns;          // D2, 内部 seam
    private final boolean allowLoopback;    // 配置注入, 默认 false

    // 校验顺序:
    // 1. scheme ∈ {http, https}                (沿用 M2 语法层)
    // 2. host 语法(DNS label / ≤253 / 尾点)   (沿用 M2 语法层)
    // 3. host 是 IP 字面量(含混合表示) -> 直接 IP 分类; 不解析
    // 4. 否则 DnsResolver.resolve(host) 全部结果逐一 IP 分类; 任一不通过 -> 拒
}
```

- IP 分类(internal `IpAddressClassifier`,纯函数):拒绝回环(v4 `127/8`、v6 `::1`)、私有(`10/8`、`172.16/12`、`192.168/16`、v6 `fc00::/7`)、链路本地(`169.254/16` 含云元数据 `169.254.169.254`、v6 `fe80::/10`)、保留(`0/8`、`100.64/10`、`192.0.2/24`、`198.51.100/24`、`203.0.113/24`、`198.18/15`、v4 组播 `224/4`、v6 组播 `ff00::/8`)、未指定(`0.0.0.0`、`::`)、IPv4-mapped(`::ffff:a.b.c.d` 按 v4 分类)。
- 混合表示(`127.1`、`0x7f.0.0.1`、`2130706433`):`InetAddress.getByName` 语义上会归一,但策略不依赖这一点——host 为纯数字/十六进制/单数字形式时按 IP 字面量路径分类,保证测试可覆盖。
- `allowLoopback=true` 时**只**豁免回环地址(`127/8`、`::1`),不豁免私有/链路本地/保留/元数据——恶意 fixture 用 loopback 即可模拟全部拦截路径,测试语义不降级。
- `BasicTargetUrlPolicy` 保留为语法层组件被新实现内嵌复用(不删,M2 单测不破)。

### D2. `DnsResolver` 内部 seam + TTL 缓存

```java
interface DnsResolver {           // visualbrowser internal, 不进 spi
    List<InetAddress> resolve(String host);  // 全部 A/AAAA 结果
}

final class InetDnsResolver implements DnsResolver {      // 生产: InetAddress.getAllByName
final class CachingDnsResolver implements DnsResolver {   // 装饰: host -> (结果, 过期时刻), TTL 30s
```

- 单测用 fake resolver 直接构造"多 A 记录含私有 IP"、"两次解析结果不同(DNS rebinding)"、"解析失败(NXDOMAIN)"场景,不依赖真实 DNS。
- 缓存仅用于**拦截热路径**(同一页面几十个子资源同 host);`TargetUrlPolicy.validate`(任务保存/就绪,低频)可不缓存,共用同一 resolver 即可。
- TTL 30s 是性能与防护窗口的折中(见残余风险文档);不做负缓存。

### D3. 请求拦截:注册点与拦截语义

```java
// BrowserContext 创建集中点(配置会话工厂 + run 的 context 工厂), 创建后立即:
context.route("**/*", route -> {
    var url = route.request().url();
    if (policy.isAllowed(url)) route.resume();
    else {
        route.abort();
        ssrfBlockedCounter.increment();
        log.debug("ssrf blocked host={}", hostOf(url));   // 只记 host, 不记完整 URL/内容
    }
});
```

- 拦截回调运行在 Playwright 分发线程,内部只做纯 JVM 判断(DNS 缓存命中为主),不触碰 lane 外共享可变状态;`context.close()` 自动注销 route。
- 拦截范围 = 该 BrowserContext 的全部请求:顶层导航、HTTP 重定向、iframe、图片/脚本/XHR 子资源,一类机制全覆盖(退出标准三条对应同一实现)。
- 导航被拦截时:Chromium 导航失败 -> 沿用 M3/M5 既有失败路径(retry -> 耗尽 -> `URL_NOT_ALLOWED`/`RETRY_EXHAUSTED`),并写 `run_event(WARN, SSRF_BLOCKED, message="host=<host>")`。
- 子资源被拦截:静默 abort + `ssrf.blocked` 计数,不产生用户可见错误(与浏览器屏蔽行为一致),DEBUG 日志只记 host。
- 导航后 `currentUrl()` 复验(M3/M5 既有)保留:拦截是第一道防线,复验是纵深。

### D5. 恶意 fixture 拓扑 + 残余风险文档

`src/test/resources/ssrf/`:

### D6. `SingleInstanceGuard`(ADR-0007)

```java
final class SingleInstanceGuard implements SmartLifecycle {
    static final long LOCK_KEY = /* 固定常量, 由类名派生稳定值 */;
    private Connection dedicated;   // DriverManager 直连, 不进 HikariCP 池

    // start(): SmartLifecycle 最早 phase, 先于 dispatcher/scheduler/seed 初始化
    //   dedicated = DriverManager.getConnection(dsUrl);
    //   成功: SELECT pg_try_advisory_lock(LOCK_KEY) -> true  -> 持有, 记 INFO
    //         false -> 抛 IllegalStateException, 启动失败, 日志含
    //                  "另一实例已持有调度锁; 确认只有一个 JAR 连接此库"
    //   stop(): SELECT pg_advisory_unlock + close (连接断开锁亦自动释放)
}
```

- 用 `pg_try_advisory_lock`(非阻塞)而非阻塞等待:fail-fast 语义,"等待前例退出"会造成静默挂起,违背决策。
- 专用直连(非池):锁必须绑定单一长连接,池化连接的回收/校验会意外释放锁。
- 放 `run` 模块(约束对象是"运行调度");模块内 internal,不建 SPI(不为单类造 port,ADR-0003 原则)。
- 不写 `system_setting` 租约行、不心跳、不 TTL——崩溃后连接断开锁即释放,无需清理(这是选 advisory lock 的核心理由,ADR-0007 记录该取舍)。
- 与既有启动序(`TaskSchemaUpgrader`、遗留运行标记已中断、dispatcher 启动)的顺序:guard 最先,失败时上述组件根本不启动。

### D7. WS `InboundGuard` + legacy 端点删除

```java
final class InboundGuard extends WebSocketHandlerDecorator {  // 挂到全部 WS handler
    // handleMessage:
    //   BinaryMessage inbound            -> close(NORMAL?) 记 INFO "binary rejected"
    //   TextMessage payloadLength > 8192 -> close 记 WARN "oversized command"
    //   速率: 每连接滑动窗口(1s 桶 ×20), 超过 20 msg/s 记满;
    //         连续 3 个窗口超限          -> close 记 WARN "rate limit"
}
```

- 实现为 `WebSocketHandlerDecoratorFactory` 注册进 `WebSocketConfig`,三个(删 legacy 后两个)端点统一覆盖,handler 自身零改动。
- 8KB 上限依据:全部合法命令(点击/滚动/键入/CANCEL/心跳)都是 <1KB 的 JSON;8KB 是 8 倍余量,不误伤。
- 二进制入站无任何合法用途(出站 JPEG 才是二进制),直接断连。
- 断连日志只含会话标识与原因,不含消息内容(脱敏约定)。
- legacy `/ws/visual` + `VisualBrowserEndpoint` 整体删除;`SecurityConfig` 的 `/ws/**` permitAll 维持(鉴权在握手拦截器,这是既有架构,不是漏洞),但删除后裸奔端点不复存在。

### D8. `BrowserLane` 崩溃检测与重建

```java
final class BrowserLane {
    // 状态: HEALTHY <-> CRASHED(重建中)
    // submit 的 future 异常完成时由调用方上报, 或 lane 在命令执行处 catch:
    //   isCrashSignal(ex)  -> TargetClosedException / "Playwright connection closed" 族
    // crash 路径(全部在 lane 自己的线程):
    //   1. markCrashed(): 后续 borrow 立即失败(池视角该 lane 不可用)
    //   2. closeCrashed(): 尽力按序 close(旧对象可能已死, 逐项吞异常)
    //   3. rebuild(): new Playwright -> launch Chromium -> 恢复 healthy
    //   4. crashRebuild counter++ ; 恢复后池可继续借出
}
```

- 崩溃信号判定集中在 `isCrashSignal` 一个函数(异常族清单写死),非崩溃异常(页面超时、元素未找到)不触发重建——只有 lane 资产本身死了才重建。
- borrow 方看到的失败:该次 submit 的 future 异常完成(既有失败路径,如 `DefaultRunPageHandle` 返回 failed result / 配置会话命令报错),**不**自动透明重试(重试语义归调用方,与 M3 页面级 retry 一致)。
- 重建期间该 lane 不回池(池满语义短暂出现),重建完成自动恢复;重建自身失败(如 Chromium 起不来)则 lane 保持 CRASHED,health 反映,不无限重试——退避后由下一次 borrow 触发再试。
- 不做 OS 进程扫描;close 路径统一走 Playwright(内部 kill 进程树)。

### D9. health 真实化 + 线程名

- `BrowserHealthIndicator`:聚合 `ConfigLanePool` + `RunLanePool` 的 per-lane 状态(healthy/borrowed/crashed),任一 lane CRASHED 且重建失败 -> DOWN;重建中 -> OUT_OF_SERVICE;其余 UP,details 带 per-lane 摘要。
- lane 线程名 `browser-lane-{pool}-{n}`(唯一),崩溃重建日志可按线程名追踪。
