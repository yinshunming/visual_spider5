# M1 Spec: 工程骨架、账号与任务基础

> Spec 草稿；review 通过后再发到 GitHub issue tracker（`ready-for-agent`, `m1`）。
> 与 [`product-spec.md`](../product-spec.md)、[`architecture.md`](../architecture.md)、[`roadmap.md`](../roadmap.md) §5、`docs/adr/0002-use-single-spring-boot-deployment.md`、`docs/adr/0003-organize-code-by-business-module.md` 配套。
> 上游约束：[M0 spike 决策文档](../spikes/remote-browser.md) 4 决策门结论与累积残余风险（spike doc §5）；M0.5 spec 已落地的 `com.visualspider.*` 模块包结构与 `Application` 启动类。

## Problem Statement

M0.5 已把 M0 spike 18 个生产类 + 12 个测试类迁入 `com.visualspider.visualbrowser`，并按 ADR-0003 建立了 `identity` / `task` / `extraction` / `run` / `result` / `shared` 6 个占位包。仓库现在是一棵 M0 spike 重排后的空骨架，没有持久化、没有账号、没有任务定义、没有版本锁文档、没有横切错误格式与启动脚本——任何后端接手人启动一次都需要重新拼凑。

M1 之前，没有人能：
- 登录一个受保护的 Web 页面；
- 创建、保存、列出、读取或删除一个采集任务草稿；
- 在两个浏览器里看到同一份任务的不同乐观锁版本——因为根本没数据库；
- 信任一个可执行 JAR 同时提供 Vue 静态资源与 REST API（pom 已就位但 `mvn package` 没跑过）；
- 在 Windows 之外的机器上启动（没有 Linux 启动脚本）。

如果不插入 M1，M2 进入配置会话产品化时就要同时承担 4 件事：建会话状态机 + 接 visualbrowser lane + 引入身份校验 + 引入任务校验。每一层的 bug 都会污染上一层的调试——回归风险叠加，与 AGENTS "不为了'更优雅'重构稳定代码" 抵触。

M1 是后续 6 个里程碑的承重墙：M2 配置会话需要 `IdentityAccess` 校验会话所有权；M3 运行调度需要 `TaskSnapshotFactory`；M4–M5 字段定义挂在 `task` 模块；M6 安全加固的所有权矩阵测试都依赖 M1 的账号体系。

## Solution

把 M1 落地为四张 issue：(a) Flyway schema + PostgreSQL 集成测试入口 + 版本锁文档 + `mvn package` 单 JAR 验证；(b) `identity` 模块（账号/会话/权限/所有权）与 Spring Security 配置；(c) `task` 模块（草稿 CRUD + 乐观锁 + `schemaVersion`）；(d) 横切：统一错误响应、滚动日志、健康检查、敏感信息过滤、Windows + Linux 启动脚本雏形。版本锁在 (a) 一并文档化。`WebSocketConfig.setAllowedOrigins("*")` 在 (a) 顺手收紧到同源 only。`TaskSnapshotFactory` 在 (c) 只挂 interface 占位，运行时不可用——M3 才接实现。

四张 issue 必须顺序推进（a → b → c → d）：(b)(c) 强依赖 (a) 的 schema；(d) 强依赖 (b)(c) 的 controller 入口与错误码表。M1 不重排 visualbrowser 已落地代码、不解决 M0 spike 决策门遗留、不实现 task 完整校验规则、不实现 task snapshot、不引入 Docker / Testcontainers / 任何新外部依赖。

## User Stories

1. As a **后端开发者接手 M2**，I want **`identity` 与 `task` 模块的 stable interface 已经定义并有单元测试覆盖**，so that **M2 接 `VisualSessionManager` 与 `TaskReadiness` 时不需要回头修改 M1 接口形状，PR diff 收敛在 M2 模块**。
2. As a **架构 reviewer**，I want **`identity` / `task` 模块的 seam 边界在 M1 即可见（仅 interface 对外暴露，PostgreSQL 与 Spring Security 隐藏在实现内）**，so that **ADR-0003 在 M2 接入 visualbrowser 之前已经完整兑现，seam 与 spike 决策门结论（lane 维持 / 全局≤3 / 4GB+4 核）不冲突**。
3. As a **首版管理员**，I want **首次启动就能用配置里声明的初始账号登录后台**，so that **我能在 30 秒内看到「登录页 + 后台账号管理」最小可用面，而不是面对一个空数据库发呆**。
4. As a **首版采集人员**，I want **用一个普通账号登录后能创建任务草稿、命名、改名、列出、读取、删除，并能编辑保存**，so that **我在 M2 接入字段与预览之前就能在真实持久化层验证我的采集思路**。
5. As a **首版采集人员**，I want **别的采集人员的任务在我的列表里不可见**，so that **我能信任这是私有部署的多租户最小隔离，而不是公共 SaaS**。
6. As a **首版采集人员**，I want **两个浏览器同时打开同一任务时，旧版本的保存被明确拒绝（看到冲突提示）**，so that **我能知道是别人先保存了，不会默默覆盖别人的工作**。
7. As a **首版管理员**，I want **能创建新账号、停用账号、重置任意账号密码，并能看到「这个账号是否已停用」**，so that **我能在一个管理面里完成团队成员生命周期，不需要直接动数据库**。
8. As a **首版运维**，I want **`mvn package` 直接产出可执行 JAR，把前端静态资源与 REST API 一起发到目标机器**，so that **我不需要 Nginx/容器化就能部署一个私有工具**。
9. As a **首版运维**，I want **Windows PowerShell 7 与 Linux shell 各有一套启动/状态/日志脚本**，so that **两套平台都按 README 跑得起来 smoke test，不需要现场摸索**。
10. As a **首版运维**，I want **健康检查能区分「应用正常 / 数据库不可用 / 浏览器 lane 暂未实例化」三种状态**，so that **故障定位时不会看到一句万能的「应用挂了」**。
11. As a **首版审计员**，I want **技术日志里看不到密码、Cookie、完整页面内容、结果值**，so that **我能相信部署后的日志可以放进日志聚合系统，不需要在采集时二次打码**。
12. As a **前端开发者**，I want **REST 错误响应有统一的业务错误码 + 用户消息 + 可选字段路径，不暴露 Java 堆栈**，so that **前端 axios interceptor 写一次就够，不用为每个端点写 try/catch**。
13. As a **首版采集人员**，I want **登录页或 README 里有 HTTP 明文传输的明显风险提示**，so that **我能立刻意识到必须把应用部署在可信 LAN/VPN 内，不能直接暴露到公网**。
14. As a **CI 维护者**，I want **没有本地 PostgreSQL 时 `mvn verify` 仍能跑通非 IT 部分，且明确日志输出跳过原因**，so that **开发者不必为了跑测试先装一个数据库，CI（M7）阶段再统一约定**。
15. As a **M3 接手人**，I want **`TaskSnapshotFactory` interface 已经挂上，但实现类标注 `M3 启用` 抛 `UnsupportedOperationException`**，so that **M3 不需要重排 M1 的接口形状，只需补实现**。
16. As a **M6 接手人**，I want **`ActorId` 已是其它模块接收的稳定身份载体，`IdentityAccess.canAccess(ownerId, actorId)` 是所有权矩阵的入口**，so that **M6 的 SSRF / WebSocket 握手复查可以直接复用同一套所有权判断**。
17. As a **M7 跨平台发布者**，I want **JDK / Spring Boot / Playwright / Vue / Vite / TypeScript / PostgreSQL / Flyway 的版本矩阵写在 `docs/specs/m1.md` 一处**，so that **M7 不需要回头考古每个依赖的选择依据**。
18. As a **未来阅读 M1 代码的工程师**，I want **代码里没有任何 `@Disabled` 测试遗留、没有 `TODO M1 后删除` 注释、没有为 spike 临时拼凑的旁路**，so that **M1 关闭时是一个干净的产品基线，不是实验代码**。

## Implementation Decisions

### D1. 版本锁与兼容矩阵（写入 `docs/specs/m1.md` 同节）

M0 spike 已实测的栈 + M1 必须固定的版本，写在 spec 顶部，所有 issue 都遵守：

| 维度 | 版本 |
| - | - |
| JDK | 21.0.11 LTS |
| Maven | 3.9.11（由 Maven Wrapper 携带，固定 `maven-wrapper.properties`） |
| Spring Boot | 3.4.13（已 `spring-boot-starter-parent` 锁定） |
| Playwright Java | 1.61.0（M1 不引入新场景；visualbrowser 复用既有依赖） |
| PostgreSQL | 16（与 Spring Boot 3.4.x + Flyway 10.x 默认兼容；本地 PG 16 已验证） |
| Flyway | 10.x（由 Spring Boot 3.4.13 BOM 锁定） |
| Vue | 3.5.x（已 `frontend/package.json` 锁定） |
| Vite | 6.x（已锁定） |
| TypeScript | 5.6.x（已锁定） |
| Node | v22.14.0（已 `frontend-maven-plugin` 锁定） |
| JUnit / AssertJ / Mockito | 由 `spring-boot-starter-test` 携带；M1 不指定额外版本 |

不引入：Docker / Testcontainers / Redis / Nginx / Elasticsearch / 任何新外部依赖。

### D2. Flyway V1 baseline

`db/migration/V1__baseline.sql`（issue (a) 落地），最小集：

- `app_user`：`id` (`BIGSERIAL`)、`username` (`VARCHAR(64)` UNIQUE NOT NULL)、`password_hash` (`VARCHAR(72)` NOT NULL)、`role` (`VARCHAR(16)` NOT NULL CHECK in `('ADMIN','COLLECTOR')`)、`status` (`VARCHAR(16)` NOT NULL CHECK in `('ACTIVE','DISABLED')`)、`created_at` (`TIMESTAMPTZ` NOT NULL DEFAULT now())、`updated_at` (`TIMESTAMPTZ` NOT NULL DEFAULT now())。
  索引：`UNIQUE(username)`、`(status, created_at)`（管理列表用）。
- `collection_task`：`id` (`BIGSERIAL`)、`owner_id` (`BIGINT` NOT NULL REFERENCES `app_user(id)`)、`name` (`VARCHAR(200)` NOT NULL)、`mode` (`VARCHAR(16)` NOT NULL CHECK in `('SINGLE_PAGE','LIST')`，M1 默认 `SINGLE_PAGE`)、`status` (`VARCHAR(16)` NOT NULL CHECK in `('DRAFT','READY')`，M1 只用 `DRAFT`)、`schema_version` (`INT` NOT NULL)、`definition` (`JSONB` NOT NULL)、`version` (`BIGINT` NOT NULL DEFAULT 0)、`created_at` / `updated_at` (`TIMESTAMPTZ` NOT NULL DEFAULT now())。
  索引：`(owner_id, updated_at DESC)`（任务列表）、`(owner_id, name)`（重名检测延后到 M2）。
  乐观锁：`version` 列在 `UPDATE` 时 `WHERE id = ? AND version = ?`，0 行命中即返回 `409 Conflict`（M1 用 409；M3 才考虑 412）。
- `system_setting`：`key` (`VARCHAR(64)` PRIMARY KEY)、`value` (`TEXT` NOT NULL)、`updated_at` (`TIMESTAMPTZ` NOT NULL DEFAULT now())。M1 仅写入 `seed.admin.username` 一行；容量/保留天数常量写在 Java 端（M6 才迁移到 DB 配置）。

V1 仅做 `CREATE TABLE` + `CREATE INDEX`，**不**做 `INSERT` / 初始管理员写入。初始管理员 seed 由 Spring Boot `ApplicationRunner` 读取 `application.yml` 的 `seed.admin.*` 写入，缺失/格式错误则启动失败（见 D5）。

不创建：`collection_run` / `run_result` / `run_event`（M3 启用）。`app_user.role` 与 `collection_task.mode` 用 `VARCHAR(16)` + `CHECK` 而不是 PostgreSQL 枚举，因为 M1 阶段扩展时不想做 `ALTER TYPE`。

### D3. `identity` 模块接口草案

ADR-0003 约束：仅通过 stable interface 对外暴露能力；隐藏 Spring Security、BCrypt、CSRF、HttpOnly/SameSite Cookie、`SecurityContextHolder`。`ActorId` 是其它模块接收的稳定身份载体（`record ActorId(long value)`），不暴露用户名/角色。

```java
// 仅示意决策，非最终代码
public sealed interface ActorRole permits ActorRole.Admin, ActorRole.Collector {
    record Admin() implements ActorRole {}
    record Collector() implements ActorRole {}
}

public interface IdentityAccess {
    ActorId currentActor();                                    // 抛 NotAuthenticatedException
    ActorRole currentRole();
    boolean isAdmin();
    boolean canAccessTask(long taskOwnerId);                    // admin 通过; owner 通过
    boolean canAccessUser(long targetUserId);                   // admin 通过; 自己通过
    boolean canRunAnyTask();                                    // admin 通过
}
```

```java
public interface AccountAdministration {
    long createAccount(String username, char[] rawPassword, ActorRole role);  // 仅 admin
    void disableAccount(long userId, ActorId actor);                          // 仅 admin; 不能停自己
    void resetPassword(long userId, char[] newRawPassword, ActorId actor);    // 仅 admin
    void enableAccount(long userId, ActorId actor);                          // 仅 admin
}

public interface Authentication {
    void login(String username, char[] rawPassword);                          // 失败抛 AuthenticationFailed
    void logout(ActorId actor);
    boolean isAuthenticated();
}
```

实现细节隐藏：BCrypt cost=12、`HttpSession` + `JSESSIONID` Cookie（`HttpOnly` + `SameSite=Lax`，不设 `Secure` 因为首版 HTTP 明文）+ CSRF `CookieCsrfTokenRepository.withHttpOnlyFalse()`（前端读 cookie 头写入 `X-XSRF-TOKEN`）+ `SecurityFilterChain` Bean。Controller 与其它模块**只接收 `ActorId`**，不接触 `Authentication` 对象与 `SecurityContext`。

### D4. `task` 模块接口草案

```java
public sealed interface TaskMode permits TaskMode.SinglePage, TaskMode.List {
    record SinglePage() implements TaskMode {}
    record List() implements TaskMode {}    // M1 占位, M4 启用
}

public record FieldDefinition(
        String name,
        FieldSource source,            // M1 占位 enum, 仅 TEXT
        String selector,               // M1 暂不校验, 存为 JSON
        String attributeName,          // M1 暂不消费
        ResultType resultType,         // M1: TEXT/NUMBER/URL
        TrimPolicy trim,               // M1: TRIM/PRESERVE
        String regex,                  // M1 暂不消费
        boolean required               // M1: 仅记账, 不参与校验
) {}

public record TaskDefinition(
        int schemaVersion,             // M1 固定 1
        TaskMode mode,
        String startUrl,
        Viewport viewport,             // M1 固定 1280x720
        List<FieldDefinition> fields   // M1 可为空
) {}

public interface TaskCatalog {
    long createDraft(TaskDefinition draft, String name, ActorId actor);   // 校验所有权; 仅自己
    TaskDraft read(long taskId, ActorId actor);                            // 所有权校验
    List<TaskSummary> listMine(ActorId actor);
    TaskDraft saveDraft(long taskId, TaskDefinition draft, long expectedVersion, ActorId actor);
                            // expectedVersion 不匹配抛 StaleTaskVersionException(409)
    void delete(long taskId, ActorId actor);                               // 仅自己 / admin
}

public interface TaskReadiness {
    ReadinessReport validate(TaskDefinition draft);
    ReadinessReport validateForRun(long taskId, ActorId actor);            // M3 启用
}

public interface TaskSnapshotFactory {
    TaskSnapshot snapshot(long taskId, ActorId actor);
    // M1 实现类抛 UnsupportedOperationException("TaskSnapshotFactory M3 启用")
}
```

`TaskDefinition` 用 Java record + Jackson 序列化为 JSONB。M1 校验规则只覆盖：schemaVersion 是 1、mode 是 SINGLE_PAGE 或 LIST（LIST 暂可写不可执行）、startUrl 是合法 http(s) URL（仅做 `URI.create` + `getScheme` in `{http,https}` + 主机非空；SSRF 完整校验延后 M6）、viewport 是 1280x720（其它值 M1 拒绝并提示 M2 启用）、fields 列表合法 JSON 字段名（`name` 非空、`name` 唯一）。

`schemaVersion` 是 int 而不是 enum：M2/M3 加 schema 时以 `schemaVersion=2/3` 引入 reader；旧 reader 仍可读旧快照。`definition` JSONB 内若包含未知字段，写入时保留、读取时不报错（`@JsonIgnoreProperties(ignoreUnknown = true)`），保证历史快照可解释。

### D5. 初始管理员 seed（启动校验 → 拒绝）

`application.yml` 顶部声明：

```yaml
seed:
  admin:
    username: ${VISUALSPIDER_ADMIN_USERNAME:}
    raw-password: ${VISUALSPIDER_ADMIN_PASSWORD:}
```

Spring Boot `ApplicationRunner`（在 `identity` 模块内）：

1. 启动时若 `username` 或 `raw-password` 为空 / 长度 < 12 / 仅空白 → 抛 `IllegalStateException`，Spring Boot 启动失败，stderr 输出明确原因（「`seed.admin.username` 未配置」）。
2. 启动时若 `app_user` 表里已存在同名 `username` → 跳过写入并日志 `WARN seed admin already present`。
3. 启动时若不存在 → 用 BCrypt(cost=12) 哈希 `raw-password` 后写入 `role=ADMIN, status=ACTIVE`。
4. 密码字段在 BCrypt 哈希后立刻从 `char[]` 数组清零（`Arrays.fill(rawPassword, '\0')`），不留 GC 残留。

明文密码仅出现在 YAML 配置与环境变量；技术日志与数据库均不存明文。M1 spec 显式约定：运维部署时必须把 `VISUALSPIDER_ADMIN_USERNAME` / `VISUALSPIDER_ADMIN_PASSWORD` 通过环境变量注入（或 Vault / K8s Secret）；README 给一段 `pwsh` 与 `bash` 示例。

### D6. Spring Security 配置（仅 `identity` 模块可见）

`SecurityFilterChain` Bean：

- 全部请求默认 `authenticated()`；`/login`、`/actuator/health`、`/error`、静态资源（`/`, `/assets/*`, `/favicon.ico`）放行；`/ws/**` 仍由 `WebSocketConfig` 单独放行（M2 才接身份握手）。
- `formLogin().disable()` / `httpBasic().disable()`：首版只走自管 `/login` JSON endpoint（M1）+ 后续 M2 接入 WebSocket 握手。
- CSRF：`CookieCsrfTokenRepository.withHttpOnlyFalse()`，前端 `axios` interceptor 读 `XSRF-TOKEN` cookie 写入 `X-XSRF-TOKEN` header；`/login` 端点豁免 CSRF（密码哈希后即建立 session）。
- Session：`SessionCreationPolicy.IF_REQUIRED`，超时 30 分钟无操作失效（首版固定常量；M6 写 DB）。
- Cookie：`HttpOnly` + `SameSite=Lax`；不设 `Secure`（HTTP 部署限制，产品 §11 已锁定）。
- `passwordEncoder()`：BCrypt cost=12。

`WebSocketConfig.setAllowedOrigins` 在 (a) issue 顺手收紧：从 `setAllowedOrigins("*")` 改为 `setAllowedOrigins()` 不带参数（即同源 only）。前端 `vite dev` 5173 → 后端 8080 仍由 `vite.config.ts` 现有 `/ws` proxy 覆盖；REST 跨源问题由前端走同源部署或显式 origin 列表（首版默认同源）。

### D7. 统一错误响应

REST 错误响应统一信封（产品 §8 / 架构 §8）：

```json
{
  "code": "TASK_STALE_VERSION",
  "message": "任务已被其他人更新，请刷新后重试。",
  "fieldPath": null
}
```

`@RestControllerAdvice` 在 `shared` 模块内：

- 业务异常 → 业务码 + 用户消息（中文，国际化延后 M7）。
- `MethodArgumentNotValidException` / `ConstraintViolationException` → 第一个字段错误 + `fieldPath`。
- `AuthenticationFailed` → 401 + `AUTH_INVALID_CREDENTIALS`。
- `NotAuthenticatedException` → 401 + `AUTH_REQUIRED`。
- `StaleTaskVersionException` → 409 + `TASK_STALE_VERSION`。
- `AccessDeniedException` → 403 + `ACCESS_DENIED`。
- 其它 `RuntimeException` → 500 + `INTERNAL_ERROR`，响应体只含 code/message，**不**含堆栈与 `ex.getMessage()`；详细堆栈写技术日志。

错误码常量集中在 `shared` 模块的 `BusinessErrorCode` enum，每个码带 `code()` + `userMessage()`。

### D8. 横切：日志、健康检查、敏感信息过滤

- **日志**：依赖 `spring-boot-starter-logging`；`application.yml` 默认 `INFO`；SQL `DEBUG` 仅在 `dev` profile。滚动策略：单文件 10MB × 10 个文件 + 30 天按日期归档。敏感信息过滤：自定义 `logging.pattern.console` / `logging.pattern.file` 增加正则脱敏（password=、Cookie=、`Authorization: Bearer`、`Set-Cookie:`、JSONB 内 `password` / `token` 关键字）；测试用 `ListAppender<ILoggingEvent>` 验证密码字段从不落盘。
- **健康检查**：`spring-boot-starter-actuator`（pom 已预备依赖路径），暴露 `/actuator/health`：包含 `db`（PostgreSQL Ping）、`browser`（visualbrowser lane 池状态，`M1` 永远 `UP` + 注释 "M2 启用"）、`diskSpace`。`/actuator/info` 返回版本与 commit hash（git-properties plugin）。`/actuator/**` 其余端点不放行（M6 才启用）。
- **不记录的内容**（架构 §7.2 / 产品 §11）：密码、Cookie、完整页面内容、结果字段值、`HttpSession` ID。`logging.pattern` 脱敏正则至少覆盖：`password\s*[:=]\s*\S+`、`Authorization:\s*\S+`、`Set-Cookie:\s*\S+`、`XSRF-TOKEN\s*=\s*\S+`。

### D9. Windows + Linux 启动脚本雏形

`scripts/windows/dev-start.ps1`（PowerShell 7，pwsh 兼容；不写 Windows PowerShell 5.1）：

1. 检查 `java -version` >= 21、`pwsh -Version` >= 7。

### D10. 单 JAR 验证与 `mvn package` 集成

`mvn package` 必须产出可执行 JAR，含：

- Flyway migration `db/migration/V1__baseline.sql`；

`mvn verify` 验证步骤：

1. 不带 `-Ppg-it`：跑全部单元测试（不依赖 PG），`ScreencastFrameProducerIT` 保持 `@Disabled`（M0 spike 决策）；失败即退出。
2. 带 `-Ppg-it`：跑全部 PG IT；PG DSN 通过环境变量或 system property 提供（如 `-Dpg.it.url=jdbc:postgresql://localhost:5432/visualspider_test`）；无 PG 时 failsafe 直接跳过并日志 `pg-it profile requested but PG DSN not set, skipping IT`，**不**静默成功——M1 spec 显式要求日志说明（架构 §9.2 末尾）。

### D11. 前端最小可用面（仅供 smoke 验证）

`frontend/` 当前只有 Vite 模板（M0 spike 留下）。M1 不做产品 UI（M2 才做配置会话），但需要最小入口供 smoke 验证：

目的是让 `mvn package` 产出的 JAR 真有可访问的页面；产品 UI 在 M2 起按里程碑叠加。

### D12. 不触动 M0.5 已落地代码

`com.visualspider.visualbrowser.*` 18 个生产类与 12 个测试类**零修改**。唯一允许的微调：

## Testing Decisions

### T1. 模块接口测试（不依赖 PG）

`identity` 模块（issue (b)）：

- `IdentityAccessTest`：以 `@MockBean` 注入 `SecurityContext`，验证 `canAccessTask(ownerId, actorId)` 矩阵：自己通过、admin 通过、其它 collector 拒绝、停用账号拒绝、未认证抛 `NotAuthenticatedException`。
- `AccountAdministrationTest`：以 mock repository 验证「admin 能创建账号」「非 admin 抛 `AccessDeniedException`」「admin 不能停自己」「重复用户名抛 `DuplicateUsernameException`」「密码 < 12 字符抛 `WeakPasswordException`」。
- `AuthenticationTest`：mock `PasswordEncoder` + `AuthenticationManager`，验证登录失败抛 `AuthenticationFailed`、成功后 session 中存在 `ActorId`。
- `TaskReadinessTest`（task 模块）：验证最小集校验：合法定义返回 `READY`；startUrl 非 http(s) → `TASK_INVALID_URL`；viewport 非 1280x720 → `TASK_INVALID_VIEWPORT`；field name 重复 → `TASK_DUPLICATE_FIELD`；schemaVersion≠1 → `TASK_UNSUPPORTED_SCHEMA`。
- `TaskCatalogTest`（task 模块）：mock repository 验证「保存草稿时 expectedVersion 不匹配抛 `StaleTaskVersionException`」「删除别人的任务抛 `AccessDeniedException`」「listMine 只返回 owner_id 匹配的任务」。
- `BusinessErrorCodeTest`（shared）：验证每个错误码 code 字符串与 userMessage 非空。
- `RestControllerAdviceTest`（shared）：用 `MockMvc` 验证各异常 → 错误响应 JSON 形状（code/message/fieldPath）+ 不暴露堆栈。

### T2. PostgreSQL 集成测试（依赖真实 PG，pg-it profile）

`db/migration/V1__baseline.sql` 由 Spring Boot 启动自动跑通；IT 通过 `@SpringBootTest` + `@AutoConfigureMockMvc` 验证：

- `AppUserRepositoryIT`：写入 / 按 username 查 / 按 role 查 / 停用后 `status` 更新。
- `TaskRepositoryIT`：写入 → `version=0`；保存草稿时 `WHERE version = 0` 命中 1 行 → `version=1`；并发场景下两条保存都带 `version=0`，一条命中一条 0 行 → 抛 `StaleTaskVersionException`（用两线程 `CountDownLatch` 模拟）。
- `TaskOwnershipIT`：采集人员 A 创建任务，采集人员 B 调用 `read/listMine/saveDraft/delete` 均抛 `AccessDeniedException`；admin 调用同样端点全部通过。
- `FlywayBaselineIT`：空数据库 → V1 跑通；重复启动（两次 `SpringApplication.run`）→ schema_version 不变、business 表不变。
- `HealthCheckIT`：mock `DataSource` 返回 connection OK / 失败 → `/actuator/health` 状态分别 `UP` / `DOWN`。
- `LogScrubbingIT`：用 `ListAppender<ILoggingEvent>` 抓取技术日志，验证：登录失败日志不含密码明文、API 错误日志不含 Authorization header、敏感字段正则脱敏。

### T3. 端到端 smoke（依赖 JAR + PG）

`scripts/e2e/smoke.ps1` / `smoke.sh`：

1. 启 PG（docker 或本机服务）；跑 `mvnw -Ppg-it package`。
2. 启动 JAR，等待 `/actuator/health` 返回 `UP`。
3. `curl POST /api/auth/login` 用环境变量里的 admin 凭据 → 拿到 `JSESSIONID` + `XSRF-TOKEN`。
4. `curl POST /api/admin/users` 创建采集人员账号；`curl POST /api/auth/login` 用新账号登录。
5. `curl POST /api/tasks` 创建草稿；`curl GET /api/tasks` 看到 1 条；`curl PUT /api/tasks/{id}` 保存草稿。
6. 第二个采集人员登录 → `curl GET /api/tasks/{id}` 返回 403。
7. 拿第一份 session 第二次保存同任务（带旧 expectedVersion）→ 409。
8. 删除任务 → `curl GET /api/tasks` 不再列出。

Linux smoke 受 M0 决策门约束（M7 才补真机），M1 spec 写 `Linux smoke: not executed in M1; see M7`。

### T4. 行为不变保护（visualbrowser）

`mvn verify` 默认跑 visualbrowser 既有 22 单测 + 13 IT（含 `ScreencastFrameProducerIT` 的 `@Disabled`）。M1 issue (a) 顺手收紧 `WebSocketConfig.setAllowedOrigins` 后，**不得修改**这 12 个测试的断言与 fixture；M1 退出标准明确包含「`ScreencastFrameProducerIT` 仍 `@Disabled`，与重构前等价」（M0.5 spec 退出标准原文）。

### T5. 优先级与价值

按架构 §9 + common/testing.md：

- T1（模块接口测试）→ 廉价快速、覆盖业务规则矩阵，先做。
- T2（PG IT）→ 真实依赖、覆盖迁移 / 锁 / 隔离；架构 §9.2 明确「不用 H2 模拟」。
- T3（端到端 smoke）→ 覆盖 acceptance 退出标准 7 条。
- T4（visualbrowser 行为保护）→ 防御 M0 spike 退化。

`@Disabled` 仅允许在 `ScreencastFrameProducerIT`（M0 spike 已存在）；M1 不新增任何 `@Disabled`。

## Further Notes

- **M1 与 M0.5 的 seam**：M1 在 `identity` / `task` / `shared` 新增代码不应触碰 `visualbrowser.*` 任何类；唯一例外是 `WebSocketConfig` 的 `setAllowedOrigins` 一行收紧（M0.5 残余风险表 §5 第 6 条）。
- **M1 与 M0 spike 的 seam**：版本锁文档基于 spike 已实测的栈（JDK 21.0.11 / SB 3.4.13 / Playwright 1.61.0 / Vue 3.5 / Vite 6）；spike 决策门结论（screencast→screenshot 回退 / lane 维持 / 全局≤3 / 4GB+4 核）原样保留，不在 M1 重测。
- **M1 → M2 的契约**：`ActorId` 已是其它模块接收的稳定身份载体；`IdentityAccess.canAccessTask(ownerId, actorId)` 是 M2 配置会话所有权矩阵的入口；`TaskReadiness.validateForRun(taskId, actor)` M1 已挂 interface 占位，M2 接实现。
- **M1 → M3 的契约**：`TaskSnapshotFactory.snapshot(taskId, actor)` M1 抛 `UnsupportedOperationException("M3 启用")`；`collection_run` / `run_result` / `run_event` 表延后 M3 创建（不在 V1 范围内）。
- **诚实标注**：M1 spec 在 Linux smoke 段落写明「Linux smoke: not executed in M1; see M7」，符合 AGENTS "本地缺少 PostgreSQL/Chromium 时要明确列出未运行的验证，不能静默跳过后宣称全部通过"。
- **与 AGENTS "每个里程碑退出标准有可复现证据"**：M1 退出标准 7 条（roadmap §5）由 issue (d) 的 `smoke.ps1` 一一对应（M1 退出标准第 5/6 条合一；M1 退出标准第 7 条由 README + 登录页 banner 一并覆盖）。
- **与 ADR-0003**：`identity` / `task` / `shared` 三个模块在 M1 首次落地稳定 interface；M2/M3 接入新模块时如果需要新增 interface，应在 ADR 体系内追加「模块边界第二阶段」记录，避免 ADR-0003 与代码长期脱节。
- **AGENTS "PostgreSQL 是唯一外部基础设施"**：M1 接入 PostgreSQL 后，应用仅依赖 PG + 本地文件系统；不引入 Docker / Redis / 任何新外部依赖。
- **AGENTS "M0–M5 只能在开发环境和受控 fixture 上验证"**：M1 验收跑在本地 PG（开发机），不连生产 DB；M7 才补跨平台真机验证。
- **password 字段强类型**：M1 全部 password 参数类型为 `char[]`，实现内 BCrypt 哈希后 `Arrays.fill(raw, '\0')`；不留 `String` 中间态。Java 21 `SecureString`-like 替代品延后 M7。
- **CSRF 与登录**：登录端点豁免 CSRF（密码哈希成功后即建立 session），避免未登录用户先要拿 token 才能登录的鸡生蛋问题。Spring Security 6 默认 `/login` 流程与我们的 JSON endpoint 不同，必须显式 `ignoringRequestMatchers("/api/auth/login")`。
- **未来读取历史快照**：`schemaVersion=1` reader 在 M1 实现；M2/M3 加 `schemaVersion=2/3` 时按"只前滚兼容"原则加 reader，不删旧 reader——`collection_run` 的快照 JSONB 可被任意历史 reader 解释。
