## Problem Statement

v0.1.0 已发布，但仍有以下 patch 级遗留：

- **M0 决策门遗留**：`roadmap.md` §11 LAN 帧 RTT 退出标准未闭环，`[ ]` 失真。
- **三个真缺口未修**：systemd OOM 与文档声明不一致；loopback 启动期无防御层；`lan-latency-sample.txt` 不是正式 md。
- **§12 候选不动**：`roadmap.md` §12 明确 "应在首版运行数据和真实用户反馈后重新排序"；v0.1.0 纯发布状态，无真实使用反馈，所有新功能（HTTPS / 登录态 / 调度 / 数组字段等）推迟。

  - 删除 [`docs/deploy/lan-latency-sample.txt`](../deploy/lan-latency-sample.txt)（已迁内容到 .md）。
  - [`roadmap.md`](../roadmap.md) §11：LAN 退出标准 `[ ]` → `[x]`，理由 "已发布验证流程，性能回归由 perf issue 跟踪，不阻塞 v0.1.1"。
  - `docs/deploy/release-notes-v0.1.1.md` §3.4 同步引用 `lan-latency.md`。
  - Acceptance：`lan-latency.md` 发布；`lan-latency-sample.txt` 删除且 `git grep` 0 命中；`roadmap.md` §11 `[x]` + 理由行；`./mvnw clean verify` 绿。

- **(2) systemd OOM Restart 修对齐**（`feature/m8.2-systemd-oom`）
  - [`scripts/linux/visual-spider.service`](../../scripts/linux/visual-spider.service) `[Service]` 段加 `RestartPreventExitStatus=137`（OOM-killed 不触发 `Restart=on-failure`）。
  - `docs/deploy/linux.md` §15：删 "OOM 视同非失败" 的临时语气，改为 "OOM-killed 不触发 systemd `Restart=on-failure`，证据见 systemd 文档 `RestartPreventExitStatus`"。

- **(3) loopback startup validator**（`feature/m8.3-loopback-validator`）
  - Spring Boot 启动钩子（`EnvironmentPostProcessor` 或 `SpringApplicationRunListener`，在 context refresh 前）实现 fail-fast：`profile != dev|it|smoke|e2e` 且 `--visualbrowser.target-url.allow-loopback=true` → 启动失败，错误信息明确指向 `docs/deploy/configuration.md`。

  - `docs/deploy/configuration.md`：allow-loopback 段落加 "仅 dev/it 使用，prod 启动会 fail-fast"。
  - [`CONTEXT.md`](../../CONTEXT.md) 加 `StartupFailFastValidator` 短定义。
  - ADR-0005 或 0006 加引用段落 "v0.1.1 起 SSRF 策略多一层启动期 fail-fast"。
  - `scripts/e2e/smoke.ps1` 加一行 loopback fail-fast 冒烟（prod 配置 + allow-loopback=true → 启动退出非零）。
  - Acceptance：启动校验逻辑 + 错误信息；IT 覆盖至少 3 场景；配置 / CONTEXT / ADR 文档同步；`./mvnw clean verify` 绿。

## User Stories

1. As a **真实采集人员**，I want **LAN 延迟有明确的验证流程文档**，so that **我能离线在物理 LAN 第二台 PC 跑采样，达标关掉 M7 退出标准，未达标按 perf bug 开 issue**。
2. As a **Linux 部署者**，I want **systemd 在 OOM 时不重启服务**，so that **OOM-killed 被视同 "内存压力真实存在"，重启不会让问题消失，人工介入有迹可循**（linux.md §15 已有此意图，代码未对齐）。
3. As a **prod 部署者**，I want **启动时就拒绝 "prod 配 + allow-loopback" 的危险组合**，so that **配置错误在运行时第一行之前暴露，而不是在某个 SSRF 触发时才报错**。
4. As a **首版后接手人**，I want **CONTEXT.md 收录 `StartupFailFastValidator` 术语**，so that **未来读到 M8-3 代码能 grep 到项目词汇**。
5. As a **首版后接手人**，I want **ADR-0005 / 0006 引用段落记录 "v0.1.1 起 SSRF 策略多一层启动期 fail-fast"**，so that **SSRF 演进链可追溯，不依赖 commit message**。

## Implementation Decisions

### D1. LAN 延迟脚本草稿升级为正式 md

`lan-latency-sample.txt`（80 行，2026-08-25 起草）的判定规则 / 失败时动作 / perf issue 模板已完整；升级动作：

- 升级到 [`docs/deploy/lan-latency.md`](../deploy/lan-latency.md)，加 frontmatter 提示（"Agent 不执行、必须在物理 LAN 第二台 PC 手工跑"）、结构化章节（前置 / 脚本 / 判定 / 失败时动作 / 约束）。
- 删除 `.txt` 文件，`git grep lan-latency-sample.txt` 全仓库 0 命中。
- `roadmap.md` §11 翻 `[x]`，理由行写 "已发布 docs/deploy/lan-latency.md 验证流程，性能回归由 perf issue 跟踪，不阻塞 v0.1.1"。
- `docs/deploy/release-notes-v0.1.1.md` §3.4 引用 `lan-latency.md`，不再引用 `.txt`。

### D2. systemd OOM Restart 修法选择

候选：`RestartPreventExitStatus=137` / `OOMPolicy=stop` / `MemoryMax` / 仅文档加强。

- 选 `RestartPreventExitStatus=137`（最小改动、与现状声明对齐、适用所有 systemd 版本 ≥ v227）。
- 单元测试：解析 service 文件确认含 `RestartPreventExitStatus=137`（正则匹配，允许有 / 无前置空格和行尾注释）。
- `linux.md` §15 同步：删 "OOM 视同非失败" 临时语气，改为已对齐到 systemd 行为的描述。

### D3. loopback startup validator 实现边界

- 启动钩子选型：优先 `ApplicationContext` `EnvironmentPostProcessor` 或 `SpringApplicationRunListener`（在 context refresh 前），保证 fail-fast 在端口绑定前生效。
- profile 判定：读取 `spring.profiles.active`，包含 `dev` / `it` / `smoke` / `e2e` 之一 → 旁路。
- 配置 key：复用 `--visualbrowser.target-url.allow-loopback=true`（M6-1 / `PublicTargetUrlPolicy` 已使用）。
- 错误信息：
  ```
  StartupFailFastValidator: --visualbrowser.target-url.allow-loopback=true in non-dev profile '<profile>';
  production startup aborted. See docs/deploy/configuration.md §<anchor>.
  ```
- 不改：`PublicTargetUrlPolicy` 运行时拦截逻辑；`IpAddressClassifier` 私有地址判定；SSRF fixture 与 IT 覆盖。

### D4. ADR 引用段落位置

候选：0005（SSRF 策略）/ 0006（单页采集执行）/ 新建 0008。

- 选 "在现有 0005 或 0006 加引用段落"，不新建 0008（理由：不是新决策，是现有决策的强化层，成本 / 收益不对等）。
- PR3 实际写时根据两个 ADR 现有内容判断哪个更接近 "运行期 SSRF 拦截" 语义，选那个加段落。
- 段落内容 30 行内："v0.1.1 起，SSRF 策略多一层启动期 fail-fast；详见 M8-3 PR 与 `docs/specs/m8.md` D3。"

### D5. 不做项（防止顺手扩展）

- §12 任何候选（HTTPS / 登录态 / 调度 / 数组字段 / 多级内容页 / 反向代理 / Docker / 移动设备）。
- lockfile / patch 升级（JDK / Spring Boot / Playwright / Vue / Node）除非有具体 CVE。
- 顺手重构（visualbrowser 模块内部 / run 模块 / extraction 模块）。
- 删除历史兼容逻辑（`PublicTargetUrlPolicy` 旧分支 / M6 advisory lock 旧路径）。
- 修改 SSRF 策略本身（M6-1 / ADR-0005 已定）。
- 新建独立 m8-acceptance 脚本（每张 issue 的 IT 已覆盖；`smoke.ps1` 加一行 loopback 冒烟即可）。
